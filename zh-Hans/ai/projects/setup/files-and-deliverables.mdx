项目文件为持续协作提供共同资料。上传的需求、分析中间文件和最终报告可以留在同一项目中，供获准参与工作的 Assistant 和成员使用。

## 使用项目资料库

在项目工作台打开**资产**，进入项目资料库：

1. 浏览文件夹或搜索文件，打开需要查看的内容。
2. 有编辑权限时，可上传资料、保存支持编辑的文件或删除不再需要的文件。
3. 预览和编辑方式取决于文件类型；不支持的格式可通过可用下载入口交给相应软件处理。

在会话中明确指出要使用的资料和目标文件，例如：

> 使用项目资料库中的产品说明和价格表，生成 `reports/comparison.md`。保留原始资料，无法确认的价格放入待核对清单。

共享存储使资料能够跨项目会话复用，但不表示每次回复都会自动读取全部文件。请在需求中说明相关文件，并确认 Assistant 有读取和处理该格式的能力。上传资料也不等同于建立了可检索的知识库。

## 区分三类内容

| 内容 | 如何理解 |
| --- | --- |
| 对话附件 | 为某次交流提供的输入，需要保持正确的会话和项目归属 |
| 项目工作文件 | Assistant 和成员在项目中使用、修改的资料，内容可能继续变化 |
| 已交付产物 | 某次执行正式提交的文件或 Artifact，具有对应的执行和版本记录 |

不要把另一项目的文件引用直接用于当前项目。切换项目后应重新选择当前获准访问的资料。

## 在派发前说明交付要求

如果需要下载结果，应在任务中写清：交付哪些文件、使用什么格式、是否需要打包，以及完成时怎样检查。例如：

> 交付最终报告和价格对比表，分别提供文件；不要打包临时缓存和原始附件。报告要包含来源日期和待确认项。

支持文件交付的外部执行器可提交明确选择的文件或压缩包。未请求文件交付时，一次执行可能只留下文本结果和工作文件。群成员任务使用普通 Assistant 输出，其交付方式取决于该 Assistant 的能力，不自动套用外部 Coding 执行器的打包方式。

## 查看和下载本次执行的产物

1. 在**项目任务**中打开目标任务。
2. 切换到**产物**，查看按执行分组的已提交文件和交付信息。
3. 打开对应执行查看器，使用该执行提供的预览或下载入口。
4. 核对文件内容是否符合当前完成要求，再记录验收决定。

工作目录路径、回复中的文件名和“已生成”文字不等于已交付文件。执行成功与文件交付成功分别记录；导出失败时，应先查看已保留的结果和交付诊断，再决定是否补交文件。

## 保留可追溯结果

验收依据应对应本次实施和确切的结果版本。后续修改工作文件，不会把旧的通过结论自动变成对新内容的认可。需要继续迭代的报告或看板，可以使用 [Artifacts](/zh-Hans/ai/agent/artifacts/index) 或[实时看板](/zh-Hans/ai/live-dashboard/index)的保存与版本能力。

项目指令和技能属于受管理内容，建议通过项目配置维护。不要把指令文件当普通附件覆盖或删除，参见[Assistant、指令与技能](./assistants-and-context)。
