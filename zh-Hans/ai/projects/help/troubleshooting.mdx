---
title: "项目与任务故障排查"
description: "排查项目不可见、任务未启动、执行结果未回复、验收受阻以及文件和定时任务问题。"
---

先定位问题发生在哪一层：项目访问、任务计划、实际执行、结果投递，还是业务验收。任务记录和执行详情比一句“已完成”回复更能说明当前情况。

## 项目或入口不可见

| 现象 | 检查与处理 |
| --- | --- |
| 没有项目入口或不能新建 | 请管理员检查项目功能是否启用，以及账号的创建权限 |
| 列表中找不到已有项目 | 确认当前组织，清除名称、状态和类型筛选，再检查成员关系 |
| Assistant 的选择器不显示项目 | 确认项目活动状态、Assistant 关联和当前用户的使用权限 |
| 群里不能修改项目关联 | 群主才能操作；关联已有项目还需要项目管理权限 |
| 业务项目不能通用改名或归档 | 从所属应用管理对应业务对象 |
| 会话中没有项目任务 Workbench | 检查会话是否已关联项目，Assistant 是否具备项目管理能力，以及部署是否包含对应视图 |

登录成功不代表已选中正确组织。请先确认组织上下文，再判断是否缺少权限。

## 有计划，但任务没有启动

插件应用维护的任务应从应用业务入口启动或重试。来源归属和同步问题见[业务任务与执行同步](../plugin-apps/business-tasks)。

创建任务、填写日期和保存依赖都只改变计划。要求负责的 Assistant 明确派发，并确认出现执行记录。

如果派发被拒绝，检查：前置任务是否已验收完成；负责人是否与执行目标一致；群成员是否已明确选入项目且仍活跃；外部执行器是否可用。外部执行还可能需要等待项目中已有尝试结束。

不要通过删除依赖或修改完成状态来掩盖未满足的前置条件。

## 执行结束，但还没有后续回复

打开任务的**执行记录**，区分实际运行状态与结果投递状态。

| 情况 | 下一步 |
| --- | --- |
| 原 Assistant 还在回复 | 等待当前轮次，结果可能已排队 |
| 会话等待输入或审批 | 完成需要的输入或审批；自动回复不会越过该状态 |
| 会话已暂停或被停止 | 在需要时手动继续，要求读取已保存结果 |
| 投递失败 | 有权限时重试已有结果的投递，不重新派发整个任务 |
| 权限被撤销或原会话不可用 | 先处理访问问题，结果不会自动转投其他会话 |

断线后重新打开会话可以恢复已保存消息，但不保证重放离线期间的每个流式片段。

## 运行成功，却不能确认完成

先检查当前任务是否仍是同一份要求，是否已产生更新的实施结果，以及验收引用的文件版本是否变化。旧结果或旧审查不能代替当前证据。

已委派独立审查时，必须有最新有效且通过的审查报告。审查失败、需要修改或无法确定时，应先处理问题；报告本身也不能替代最终完成决定。

同时确认用户具有项目编辑权限，且该任务不是由业务应用独立管理。

## 执行失败或状态未知

查看对应尝试的错误、已捕获输出和保留文件，先确认实际做过哪些工作。模型欠费、连接器失效和执行环境问题修复后，再明确开启新尝试。

“状态未知”不能证明运行没有发生。直接重跑可能重复修改文件或外部系统，应先检查已有执行。群聊失败消息可从**助手处理记录**查看对应尝试。

## 找不到文件或无法下载

在**产物**页确认是否存在正式交付：回复里的文件路径可能只是工作文件。查看是否未请求交付、导出失败，或下载权限已变化。执行成功与文件导出成功需要分别检查。

检查工作文件时，打开当前项目的**资产**页，不要使用另一项目或个人会话中的旧引用。更多说明见[共享文件与交付物](../setup/files-and-deliverables)。

## 日期、进度或界面看起来不一致

- 没有百分比：当前执行或应用没有提供可确认的进度，继续查看状态。
- 计划时间与真实时间不同：计划表达预期，执行区间表达实际发生的过程。
- 看不到部分任务：清除搜索和状态、负责人、类型筛选，展开任务树。
- 保存计划提示冲突：刷新后重新核对协作者已经保存的修改。
- 应用任务暂未更新：等待同步并刷新，确认所属应用操作确实成功；持续异常时联系维护者。

## 定时任务被暂停

检查执行用户是否仍在项目中、项目是否归档、Assistant 是否仍关联且可访问，以及所选连接器是否有效。更换执行用户需要目标成员确认。修复后由有权限的管理者恢复安排。

## 向管理员提供什么

说明项目与任务名称、发生时间、所选 Assistant、看到的状态、最后一次操作以及希望得到的结果。可以提供已授权的执行详情链接和可见错误摘要；不需要发送账号令牌或完整私密资料。
