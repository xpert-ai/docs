应用关联平台项目后，可以围绕同一工作目标组织 Assistant、会话、资料和任务。任务接入是其中一部分；项目还为应用提供共同的协作上下文。

## 业务对象与平台项目

对于需要独立业务对象的应用，例如一份标书或一个处理案例，应用维护业务记录与平台项目的稳定关联。用户从应用入口创建和打开业务对象，平台项目提供共同资源及任务入口。

应用可声明自己的项目类型，使项目列表和会话选择器能够按应用和类型组织项目。打开关联业务对象的项目时，由应用解析到对应业务入口；不能只靠项目名称猜测归属。

在应用的对话界面中展示这些类型、选择项目或固定当前项目，参见 [ChatKit：项目与项目类型选择](/zh-Hans/ai/chatkit/chatkit-projects)。

项目名称和生命周期随业务对象协调。业务对象归档后，关联项目应反映归档状态；重试关联操作继续使用同一项目。通用项目入口不能代替应用任意改名、复制、归档或删除这类项目。详见[项目类型](../setup/project-types)。

## Assistant 与共同工作方法

应用可以在首次预配项目时连接入口 Assistant 及其依赖的外部 Assistant，使它们围绕同一项目协作。已有项目的 Assistant 成员关系会被保留；再次同步项目不会自动加回已移除的 Assistant，也不会因为模板增加依赖就自动扩充成员。

在项目中维护共同指令和技能，可以统一术语、资料使用方式和输出标准。Assistant 仍需具备对应工具和运行权限；任务列表中显示了某位负责人，并不代表其全部能力都已启用。

项目成员、Assistant 连接和应用的业务角色分别管理，操作方法见 [Assistant、指令与技能](../setup/assistants-and-context)。

## 资料、工作文件与正式成果

| 内容 | 推荐使用方式 |
| --- | --- |
| 共同输入资料 | 放入当前项目的文件范围，由获授权的 Assistant 和成员使用 |
| 应用产生的工作文件 | 通过 SDK 文件能力保存并保留带范围的文件引用，供后续任务读取 |
| 业务内容与校验记录 | 由应用维护其业务关系和版本，按业务入口查看 |
| 可下载的正式交付物 | 通过实际交付流程保存；使用平台 Artifact 时提供已提交版本的引用 |
| 项目或结果资源卡片 | 在资源保存成功后提供导航入口，点击时继续检查访问权限 |

工作文件写入成功、任务执行成功和交付成功是三个结果。任务同步本身不会上传文件，也不会将输出摘要转换成 Artifact。不同执行方式提供的产物入口可能不同；查看成果时以应用保存的版本或平台已提交交付物为准。

跨后台任务传递文件时，插件应保存平台返回的文件引用，而不是仅记录执行环境中的绝对路径。用户无需管理这些技术标识；实际使用可参见[共享文件与交付物](../setup/files-and-deliverables)。

## 两层授权一起生效

平台项目访问与应用业务授权必须同时满足。SDK 的项目访问能力帮助应用查询可读项目和检查编辑、管理权限，但不会替应用决定谁能操作某个业务对象。

| 授权关系 | 决定什么 |
| --- | --- |
| 已发布 Assistant 的使用授权 | 用户能否进入并运行应用 Assistant |
| 项目成员及角色 | 用户能否读取、编辑或管理这个平台项目 |
| Assistant 与项目的连接 | 该 Assistant 是否参与当前项目 |
| 应用业务权限 | 用户能否查看或修改对应业务对象及执行特定操作 |
| 文件、知识库和连接器授权 | 当前操作可以访问哪些资料与外部系统 |

获准使用应用不代表能看到所有项目，加入项目也不代表能使用全部连接器或管理应用空间。连接器必须来自当前操作获准使用的绑定；插件应在读取、业务操作、后台同步和执行跳转时保留同一用户、租户、组织和项目范围。

找不到项目或被拒绝访问时，先确认当前组织和项目，再分别检查项目成员关系、Assistant 使用授权及业务对象权限。管理员操作参见[成员与权限](../setup/members-and-permissions)和 [Assistant 与应用授权](/zh-Hans/ai/system/permissions/assistant-application-authorization)。

## 业务界面与任务界面配合

应用的专用界面负责目录、表单、案例材料等专业操作；平台的项目任务界面负责共同的任务跟踪和执行查看。二者可在同一会话 Workbench 中使用，无需应用重新实现整套任务树和甘特图。

已接入的应用可以提供打开项目任务的按钮或 Agent 工具，也可以在 Workbench 菜单中按需打开。资源卡片只提供已保存资源的入口，不会赋予权限、自动验收或重跑任务。

面向开发者的能力对应关系见 [SDK 接入指南](./sdk-integration)。
