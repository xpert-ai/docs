项目也是插件应用可以复用的平台能力。标书编制、业务案例处理等应用可以将自己的业务对象关联到一个 Xpert 项目，再把业务流程中的任务同步到平台项目任务中。用户在应用里推进专业工作，在项目里查看共同的任务、负责人、依赖和执行过程。

这类集成通过 Plugin SDK 提供的项目预配、任务、访问控制、文件和视图扩展等能力完成。应用负责业务规则，平台承载协作空间与统一任务体验。

应用选用、启用和日常业务操作见独立的 [Plugin Apps](/zh-Hans/ai/applications/index) 栏目；从用户视角了解项目配合方式，可阅读[项目与任务协作](/zh-Hans/ai/applications/app-guide/projects-and-tasks)。

## 用户获得什么

| 使用场景 | 集成后的体验 |
| --- | --- |
| 在业务应用中创建项目 | 应用完成业务设置后，关联的平台项目提供协作入口，重试复用同一项目 |
| 应用拆分业务任务 | 任务可以出现在平台统一视图中，无需用户再手工录入一份计划 |
| 多位 Assistant 分工 | 可以查看任务负责人、依赖、当前状态和历史执行尝试 |
| 一边对话一边处理业务 | 在会话 Workbench 按需打开项目任务，与应用自己的业务视图配合使用 |
| 检查某次失败或返工 | 从对应执行记录进入实际过程，保留同一任务的多次尝试 |
| 项目持续推进 | 共同资料、参与者和任务记录围绕同一项目积累 |

接入项目不会自动启动业务工作。创建、同步、查看任务和实际执行是不同操作；启动、重试与验收应从应用提供的入口完成。

## 以标书应用为例

产品能力、使用步骤及项目任务协作见 [Bid Studio 标书应用](/zh-Hans/ai/applications/bid-studio/index)。

标书应用保留自己的目录、正文、配图和材料处理流程。主 Assistant 制定业务计划后，应用将这些工作映射为项目任务：阶段显示为汇总节点，目录或章节工作显示为任务，前置关系显示为依赖，负责的 Assistant 与各次执行保留在对应任务上。

使用时可以按以下路径查看：

1. 在标书应用中选择或创建项目，完成应用要求的业务配置。
2. 通过应用安排本次工作，例如准备目录、编写选定章节或处理配图。
3. 在 Workbench 的添加视图菜单中打开**项目任务**。支持该工具的标书 Assistant 也可响应“打开当前项目的任务树和时间线”。
4. 查看阶段和章节的任务树，在甘特图中对照计划与实际执行。
5. 打开具体尝试检查运行过程；修改内容、重新安排工作和确认业务结果时，继续使用标书应用的流程。

这里只展示接入方式。可用业务步骤、任务类型和启动入口由具体应用决定；安装任意插件并不会自动生成这套任务集成。

## 应用与平台分别管理什么

| 内容 | 主要管理方 |
| --- | --- |
| 业务对象、业务计划、任务拆分和前置条件 | 插件应用 |
| 业务任务的状态、启动、重试和验收规则 | 插件应用 |
| 平台项目成员与访问检查 | 平台；应用继续检查自己的业务授权 |
| 项目任务的统一标识、视图和执行定位 | 平台 |
| 平台任务视图中的计划日期和预计时长 | 有项目编辑权限的用户，通过平台排期操作维护 |
| 业务文件、正式成果及其版本 | 由生成它们的应用或执行流程保存，并提供对应访问入口 |

应用任务保留来源归属。平台通用任务工具不会代替应用验收，也不能绕过应用规则修改其业务状态、层级或依赖。应用定义的“已完成”含义应在业务流程中说明，不能只根据一次 Agent 运行成功来判断。

## 使用前准备

管理员需要安装并初始化支持项目集成的应用，开放入口 Assistant 的使用权限，并确认用户具有目标项目和业务对象的访问权限。应用还需提供与当前平台匹配的任务接入和 Workbench 能力。

项目入口、任务同步和业务执行分别验证：能打开应用，不代表已创建项目；能看到任务，不代表任务正在运行；执行成功，也不代表业务已验收。具体接入步骤见 [SDK 接入指南](./sdk-integration)，日常状态判断见[业务任务同步](./business-tasks)。
