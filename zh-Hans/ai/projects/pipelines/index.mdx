项目流水线把多步骤工作放在共同的视图中：谁负责哪个阶段、当前停在哪里、发生过哪些执行，以及需要谁处理。它适用于已接入项目的业务应用，也适用于由平台协调执行的流程。

## 打开已有流水线

在项目工作台或会话 Workbench 中打开**项目任务 → 流水线**。进入页面直接展示已有流水线；只有主动点击**配置流水线**才打开配置窗口。打开页面、切换视图和刷新不会启动任务。

当前项目没有流水线时，先确认对应应用是否已经创建流程，或按[配置与应用接入](./configuration-and-apps)配置可用模板。安装插件、保存配置和产生一次业务流程是不同的步骤。

## 项目、流水线和轮次有什么区别

| 选择范围 | 表示什么                                     | 示例                                       |
| -------- | -------------------------------------------- | ------------------------------------------ |
| 项目     | 共同的目标、成员、Assistant、文件和访问范围  | 某个产品的交付项目                         |
| 流水线   | 该项目内某个具体对象或工作项的流程实例       | 一份业务单据的处理流程，或一次代码审查流程 |
| 轮次     | 同一流水线按输入版本和处理周期保留的一次快照 | 输入更新前后的两个处理周期                 |

左侧选择框切换**当前项目中的流水线实例**，不是切换项目，也不是选择配置模板。实例名由应用提供，可能与项目名相似。旁边的轮次选择框用于查看当前或历史轮次。一个项目可以有多个流水线实例，每个实例可以保留多轮记录。

## 阅读阶段泳道

- **横向阶段**表示流程顺序。标题、图标和分支条件标签来自配置或应用提供的数据。
- **纵向泳道**表示职责分工。Assistant 信息放在泳道上；选择泳道或使用泳道筛选可以聚焦相关工作。
- **节点卡片**显示本步骤的业务情况。节点内的圆点只代表属于该节点、该轮次的执行，不重复展示 Agent 名称。
- **控制节点**在相关流程位置展示分支、汇合等关系，不单独占用底部泳道。
- **分支连线**表达路径关系。它不代表所有分支都会执行，具体采用的路径以流程记录为准。

顶部状态汇总帮助定位已完成、运行中、等待人工处理或受阻的节点。状态的含义取决于业务判断和实际执行记录，不能只看颜色判断是否已交付。

## 查看执行和节点详情

切换到**执行时间轴**查看已记录执行的时间分布。点击节点打开详情，查看概览、执行记录和证据；点击执行圆点打开对应的那次执行。

节点详情中可用的业务工作台入口和节点操作由当前应用与权限决定。历史轮次保留追溯信息，不用于推进当前业务。没有入口时，不能以相邻节点或其他执行替代。

关于“执行成功但节点仍受阻”、圆点去重及统计口径，见[执行记录与历史轮次](./executions-and-history)。

## 在不同入口之间切换

Cloud 与 Desktop 会话中的项目任务 Workbench 共享流水线视图。业务工作台可以用于处理专业内容，再返回对应流水线和节点；可恢复的选择状态按用户和项目保存，无效或已失去权限的目标会重新校验。

Desktop 的独立项目入口打开已配置的平台页面。应用入口、模板和执行查看能力取决于部署、插件及授权，并不因项目页面可见而自动获得。
