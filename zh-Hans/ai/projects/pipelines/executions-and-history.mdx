一次执行成功，表示执行器完成了这次运行。节点是否业务完成，还取决于验收、审批或应用自己的判定。流水线保留这两类信息，便于说明流程为什么仍停在某一步。

## 圆点属于哪一次执行

节点圆点仅显示明确归属于**本节点、本轮次**的执行。切换到新轮次，不会把上一轮的执行补进来；回到历史轮次，仍可查看当时对应的执行。

同一执行被多个来源重复报告时会合并展示，泳道汇总也会去重。重试产生的不同执行仍分别保留。没有可靠归属的记录不会根据 Assistant 名称或相同任务猜测关联。

点击圆点打开对应执行；点击卡片打开节点详情。项目可读与执行详情可读是不同的权限。如果执行已删除、目标不可访问或历史记录缺少导航信息，界面不能保证打开它，但也不会跳到另一条执行作为替代。

## 历史业务快照与执行终态

| 看到的情况                         | 如何理解                                           |
| ---------------------------------- | -------------------------------------------------- |
| 执行成功，业务仍受阻               | 执行已经结束，但业务问题、审核或输入条件尚未解决   |
| 历史业务状态没有变化，执行变为成功 | 历史快照仍保留原业务判定，同时展示已确认的执行终态 |
| 新轮次没有圆点                     | 这一轮尚未记录对应执行；旧轮次的执行不会沿用       |
| 请求已提交，但没有终态             | 仍需等待执行或核对结果；提交成功不等于执行成功     |
| 已请求取消，仍未显示已取消         | 取消尚未得到执行器确认，不应当作已经停止           |

历史轮次用于审计和追溯。查看历史不会重写过去的业务结果，也不会自动启动新一轮。

## 使用统计

**统计**聚焦当前流水线；**项目统计**用于查看项目范围的执行情况。它们与泳道顶部的当前业务状态汇总回答不同的问题。

| 维度           | 可以了解什么                                         |
| -------------- | ---------------------------------------------------- |
| 流水线与模板   | 哪些流程产生了执行，执行数量和结果如何               |
| 执行器         | 各 Assistant 或执行目标承担了哪些执行                |
| 执行状态       | 成功、失败、取消和未完成执行的分布                   |
| 耗时           | 有完整起止时间的执行的平均、中位数及高分位耗时       |
| 重试           | 已明确记录的技术重试；同一任务的额外执行不必然是重试 |
| 模型用量与成本 | 已提供的用量、币种和费用；缺失数据不等于零成本       |
| 排队与人工等待 | 有相关时间记录时的等待情况                           |

执行统计按实际开始时间筛选，时间范围包含开始边界、不包含结束边界，单次最多覆盖 93 天。当前业务状态汇总反映当前轮次，并不随统计时间窗口还原成过去某一天的业务快照。

成功率以成功、失败和取消的终态执行为分母，不把运行中执行算成失败。没有终态样本时没有可计算的成功率。缺少耗时或费用的数据会影响覆盖范围；不同币种的金额不直接相加。

同一执行可能被多个流程引用，因此总计去重后不一定等于各行相加。比较结果时，先确认项目、流水线、时间范围和数据覆盖情况。

## 排查记录异常

1. 确认选择了正确的项目、流水线和轮次。
2. 刷新一次，检查节点详情里的执行记录和业务状态。
3. 若记录仍不匹配，保留节点、轮次和执行的上下文，由管理员或应用维护者核对关联。

刷新只同步显示。对结果未知的操作，应先核对原执行，不要通过连续点击重新启动来“补记录”。业务处理入口见[配置与应用接入](./configuration-and-apps)。
