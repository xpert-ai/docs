平台提供共同的流水线视图、执行追踪和权限边界。业务应用提供专业的输入、判定、证据和工作台。不同应用可以复用项目流水线，而不必使用相同的业务规则。

## 配置流水线

1. 进入目标项目的**项目任务 → 流水线**。
2. 主动点击**配置流水线**，选择当前可用的模板。
3. 按表单选择模板要求的角色、执行器和允许配置的参数。
4. 检查提示并保存。遇到能力不支持、角色不可用或权限不足时，先处理对应原因。

保存配置形成该项目使用模板的绑定，不意味着已经开始执行。已有应用流程可能由应用创建并同步，应从相应业务入口建立实例。配置窗口不会因为进入页面或刷新自动打开。

模板、参数和可选执行器由已加载的插件及宿主能力决定。列表为空时，先确认插件实际可用、组织与项目上下文正确，以及当前用户有权配置。

## 推进工作

在当前轮次的节点详情中查看可用操作、禁用原因和业务工作台入口。按应用提示准备输入并明确提交；需要审核或决定时，由有权限的用户处理。只打开工作台或刷新页面，不会触发下一步。

提交后分别检查操作是否已接受、执行是否结束、业务是否完成。结果未知时应等待或核对原操作；取消也需要确认最终状态。历史轮次的详情用于追溯，不提供推进当前业务的操作。

## 两类流程如何接入

| 接入方式     | 谁决定流程推进                                             | 项目流水线提供什么                           |
| ------------ | ---------------------------------------------------------- | -------------------------------------------- |
| 应用管理流程 | 应用管理自身状态、路由和业务操作                           | 接收快照、展示泳道、关联执行、打开业务工作台 |
| 平台协调流程 | 平台按配置组织步骤、依赖和派发；插件提供专业执行与结果判定 | 管理运行和节点状态、执行追踪、人工处理及恢复 |

应用管理的流程不会仅因为显示在项目中就改由平台推进。平台协调的流程也不会把专业规则写入公共界面。开发接入职责可从[插件应用 SDK 接入](../plugin-apps/sdk-integration)继续了解。

## BOM 应用示例

BOM 应用负责文档与产品输入、BOM 匹配、变更判断、主数据、报价和后续业务工作台。接入后，项目流水线呈现这些阶段、职责泳道、可读分支条件和对应执行记录。

用户从应用入口创建或选择业务场景，再到项目流水线跟踪进展；需要处理专业数据时，从节点或业务工作台入口进入应用。公共页面不决定什么是有效 BOM，也不代替应用审批。

这些入口取决于配套插件及其迁移验收。旧 BOM 泳道应在所需功能迁移验收通过后下线，不能仅因新页面可见就停用。

## Code Review 应用示例

Code Review 应用提供待审查代码与版本、角色分工、审查标准、问题核验和结果归档。项目流水线组织和显示准备、并行审查、汇总、核验及需要人工处理的步骤。

本地 Git 审查可以将结果留在平台。是否支持远程 PR、发布评论或其他外部动作，由所用模板、插件及授权决定；不能从“审查成功”推断已向代码托管平台发布结果。

## 使用边界

阶段标签、图标、业务入口和证据由配置与应用提供。未提供可读条件标签的流程可能仍显示技术标识，维护者应完善对应配置，不能依赖公共组件自动翻译业务条件。

具体模板是否可用，以部署中的插件版本、Assistant 配置、宿主能力和授权为准。预算扩展、自动续轮及其他尚未交付的能力不因模板出现相关字段而自动启用。
