title: "群聊项目协作"
description: "在群里关联项目、选择参与的 Assistant，并通过负责人和依赖分批派发、验收与交付。"
---

当一项工作需要多位 Assistant 分工时，可以在群聊中关联项目。群聊呈现讨论和协作过程，项目任务保存正式分工、依赖、执行和验收记录。Desktop 与 Cloud 使用相同的群项目入口。

## 准备群和项目

1. 为协调工作的 Assistant 开启**项目管理**，使用支持工具调用的模型。
2. 创建群聊，邀请具备相应能力的 Assistant。执行成员如果也要读写项目任务，同样需要项目管理能力。
3. 群主打开输入框下方的**选择项目**菜单，选择已有项目，或填写名称新建项目。
4. 确认参与项目的 Assistant，保留主 Assistant，然后提交。取消确认不会创建项目。
5. 从 Workbench 打开**项目任务**，检查项目范围是否正确。

关联已有项目需要项目管理权限。成为群主或群成员，不会自动获得该项目的编辑权限。

## 管理参与的 Assistant

绑定后，同一个项目菜单显示项目名称，并提供**管理参与的 Assistant**。群主可以加入其他符合条件的群成员；非群主可以查看，不能修改。

只有明确选入项目、仍处于活跃状态且已关联该项目的 Assistant 群成员，才可以接收本群的正式任务。任务负责人需要与所选执行成员对应。

群项目确定后不能从此菜单切换到另一个项目。此入口用于增加参与者，取消勾选已参与者不会作为移除项目关联的方式。建议在正式运行前完成项目和成员设置。

## 用两批任务完成报告

向协调 Assistant 说明：

> 请安排分析员调研竞品、数据员核对价格。两项验收完成后，让写作员编写报告。保存每项任务的负责人、依赖和完成要求，发现问题先返工，最后交付对比表与报告。

| 任务 | 负责人 | 前置条件 |
| --- | --- | --- |
| 调研竞品 | 分析员 | 无 |
| 核对价格 | 数据员 | 无 |
| 编写报告 | 写作员 | 前两项都已验收完成 |

协调 Assistant 先保存三个任务，明确派发前两项。不同成员可以并行执行；同一成员的正式任务需要等待自己的执行机会。结果返回后，协调 Assistant 检查并验收，再明确派发报告任务。

前两项仅仅运行成功，或者群里已经出现结果回复，都不满足“已验收完成”的依赖要求。提前派发报告会被拒绝。

这里的分批由任务依赖和协调者的派发动作表达。单纯建立父子任务或在消息中写“第二批”，不会自动建立调度关系。

## 在群中跟踪工作

执行成员的结果保留在群聊中；正式执行结束并记录结果后，协调 Assistant 才据此继续验收。任务视图可以查看每次尝试，返回群聊可以继续追问。

普通群消息唤醒某位 Assistant，不会自动创建项目任务。需要正式跟踪的工作，应明确要求协调者保存任务并派发。

如果执行失败，先查看消息下方的原因或**助手处理记录**。修复模型、授权或工具问题后，再明确安排新的尝试。用户停止、成员移除或权限撤销会限制自动续跑。

## 交付与验收

执行成员应提供与完成要求对应的结果。群成员派发使用普通 Assistant 输出，不自动附带外部 Coding 执行器的文件打包或独立审查能力。

由负责的 Assistant 或有权限的用户依据当前结果作出验收或返工决定。多次尝试保留在同一个任务中；不要为了掩盖失败记录重复创建同名任务。
