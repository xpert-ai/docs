在日常开发中，你可能希望助手帮你查看本机环境、在指定目录中执行命令、生成文件，或者每天定时汇总项目进展。Bosi 桌面应用把这些能力放在同一个窗口里：助手和它的默认沙箱仍然运行在 Xpert 服务端，只有在你明确批准后，命令才会在你的电脑上执行。

本教程以“让助手在本机测试目录中执行命令并核对结果”为例，介绍如何准备助手、配置本机终端、审批命令，以及如何连接自己的 Xpert 服务和配置自动化。

## 完成本教程后，你可以

- 在 Bosi 中与助手协作处理开发任务，使用插件和交付文件。
- 配置本机终端，并理解三种执行权限的区别。
- 在对话中审批或拒绝助手请求的本机命令。
- 区分本机命令、服务端沙箱命令和云电脑三种执行位置。
- 将 Bosi 连接到自行部署或本地开发的 Xpert 服务。
- 为助手配置定时计划等自动化。

如果还没有安装 Bosi，请先阅读 [Bosi 桌面应用使用指南](/zh-Hans/ai/tutorial/bosi-desktop-user-guide)。

## 开始前的准备

| 准备事项 | 如何确认 |
| --- | --- |
| 已登录的 Bosi | 能在 Bosi 中选择组织和助手并正常对话 |
| macOS 原生应用 | 本机终端仅在 macOS 原生应用中可用 |
| 支持工具调用的模型 | 组织为助手配置的模型支持工具调用 |
| 已启用桌面 Shell 的助手 | 管理员已在 Xpert Studio 中为该助手连接 **Desktop Shell** 中间件并发布 |
| 匹配的服务端版本 | Xpert 服务端、Bosi 和 ChatKit 的版本相互匹配 |
| 一个测试目录 | 准备一个可以随意写入文件的目录，用于首次验证 |

本机终端的功能和限制可能随版本调整，以你所用版本的界面提示为准。

## 第一步：与助手协作处理开发任务

在 Bosi 中选择助手后，右侧的对话区域提供消息、附件、历史会话、工具、技能、连接器和工作台。处理开发任务时，常用的方式有：

- **描述目标，让助手拆解**：直接说明要完成的工作和验收方式，例如“检查当前项目目录结构，并说明如何运行测试”。
- **上传附件**：把需要分析的文件作为附件发送给助手。
- **选择插件**：管理员导入插件后，有编辑权限的用户可以在 **发现与添加 → 插件** 中把插件添加到专家所在的工作空间，再在对话的 **插件** 菜单中选择使用。添加插件不会自动在对话中选中它。
- **查看交付文件**：助手生成文件后，点击对话中的交付卡片，可以预览交付时保存的文件版本并下载。暂不支持预览的格式可以直接下载。

如果你有工作空间的编辑权限，可以在助手的 **编辑资料** 中调整模型、能力和提示词，点击 **保存并发布** 后生效。这些专家配置会影响此专家的所有使用者；个人资料则只保存在本机。需要更复杂的编排时，选择 **在 Xpert Studio 中编排**。

## 第二步：配置本机终端

打开 **设置 → 本机终端**，在这里管理这台电脑上的命令执行：

| 设置项 | 说明 |
| --- | --- |
| 电脑名称 | 审批卡片和命令结果中显示的电脑名称 |
| Shell | 选择 zsh 或 bash |
| 默认工作目录 | 命令的起始目录。首次验证时建议设置为测试目录 |
| 命令搜索路径 | 执行命令时查找可执行程序的路径 |
| 执行权限 | 每条命令先询问（默认）、始终允许此组织的命令、禁止执行 |

修改后点击 **应用 Shell 设置**。本机终端的更改需要在该页面单独应用，不受设置页底部 **保存设置** 的影响。应用 Shell 设置会断开当前连接并撤销尚未执行的授权，下一次命令请求时按新设置重新连接。

三种执行权限的区别：

| 执行权限 | 效果 |
| --- | --- |
| 每条命令先询问 | 默认选项。每条命令执行前都会在消息中显示审批卡片，批准一次只执行这一条命令 |
| 始终允许此组织的命令 | 不再逐条询问，后续命令直接执行 |
| 禁止执行 | 不显示审批卡片，也不执行任何本机命令；正在运行的命令会被停止 |

执行权限仅适用于当前账号、当前组织和这台电脑。除非你完全信任该组织中会请求本机命令的助手，否则建议保留 **每条命令先询问**。

无需手动连接或为会话单独授权：助手请求本机命令时，Bosi 会按需自动连接。

## 第三步：请求并审批本机命令

在已启用桌面 Shell 的助手对话中发送：

```text
请在本机执行命令：查看当前操作系统和当前目录，
然后在当前目录写入一个名为 bosi-test.txt 的文件，内容为 hello。
完成后告诉我命令的退出码。
```

使用默认的 **每条命令先询问** 时：

1. 助手请求本机命令后，消息中会出现审批卡片，写明要执行的命令、电脑、工作目录和访问说明。
2. 核对命令内容。在你作出选择之前，命令不会执行。
3. 在卡片上选择只允许这一次执行，或者拒绝。卡片上的权限入口会打开本机终端设置。
4. 批准后，命令在本机执行，输出和退出码返回给助手。下一条命令需要再次审批。
5. 拒绝后，命令不会执行。助手应停止这次操作，不会改用服务端 Shell 代替执行。

完成后，在测试目录中打开 `bosi-test.txt`，确认文件内容与预期一致。以实际文件和退出码为准，不要只看助手的文字描述。

### 查看和停止命令

在 **设置 → 本机终端** 中可以查看最近的命令及其状态（等待中、运行中、已成功、已失败、已取消、已超时、已拒绝、未知）。需要中断正在运行的命令时，点击 **停止命令**。

状态为“未知”时，表示无法确认命令是否完成。Bosi 不会重复执行这条命令；请自行检查实际结果，再决定是否重新请求。

## 了解本机命令的执行方式

### 安全边界

- 命令以你当前登录的操作系统用户权限执行。工作目录只是起始目录，不是隔离沙箱，不会限制文件访问范围。
- 命令的输出会发送给 Xpert，并保存在服务端。输出中可能包含业务数据，请避免执行会输出敏感信息的命令。
- 每条命令使用一个新的非交互 Shell，只继承少量环境变量，不会继承平台账号或设备凭证。
- 不提供交互式终端（PTY）、交互输入、持续的 Shell 会话、文件同步或本地智能体运行时。需要交互输入的命令无法正常使用。

### 使用限制

| 项目 | 限制 |
| --- | --- |
| 并发命令 | 每台电脑同时只执行 1 条命令，其他请求会被拒绝 |
| 电脑离线 | 直接返回离线，不会排队，也不会改用服务端沙箱 |
| 同步等待 | 10 秒；超过后助手通过查询状态获取最终结果 |
| 命令超时 | 默认 60 秒，单条命令最长 600 秒 |
| 单条命令保留的输出 | 1 MiB，超出部分会被丢弃 |

### 何时会停止

- 关闭 macOS 窗口后，应用和本机终端仍在运行。
- 切换组织、修改服务连接、退出登录或退出应用，都会停止本机终端。
- 重启应用后，已选择的执行权限会保留，但临时授权不会保留。
- 已过期的审批无法执行。请拒绝或停止这次请求，再发起新的请求。

## 区分三种执行位置

同一个助手可以同时具备多种执行能力。请在提问时说明希望在哪里执行，并核对返回结果中的执行位置。

| 执行位置 | 由什么提供 | 适合的任务 |
| --- | --- | --- |
| 本机电脑 | **Desktop Shell** 中间件 + Bosi 本机终端 | 查看或操作你电脑上的项目和文件，需要你审批 |
| 服务端沙箱 | **Sandbox Shell** 中间件 | 在服务端隔离环境中执行代码和命令，详见[沙箱功能](/zh-Hans/ai/agent/sandbox) |
| 云电脑 | 云电脑类助手 | 让助手操作服务端电脑及其中的应用 |

需要在服务端执行命令时，管理员可以在为助手连接 Desktop Shell 的同时保留 Sandbox Shell。验证本机执行时，服务端沙箱返回的结果不算作本机执行。

云电脑类任务需要支持视觉和工具调用的模型，组织中是否提供此类助手以服务端配置为准。

## 连接自己的 Xpert 服务

开发或测试时，可以把 Bosi 连接到自行部署或本地运行的 Xpert 服务：

1. 在登录页点击 **连接设置**，或在登录后打开 **设置 → 服务连接**。
2. 填写 API 服务地址、Xpert 网页地址和 ChatKit 地址。远程服务需要使用 HTTPS；本机 `localhost` 地址可以使用 HTTP。
3. 等待页面检查地址和证书。使用你信任的自签名证书时，开启 **允许不受信任的服务证书**。此设置同样作用于本机终端到所配置 API 服务的连接。
4. 保存设置，重新登录。

部署方需要注意：

- 本机终端通过 API 服务的 Socket.IO 端点（`/socket.io/`）建立 WebSocket 连接。反向代理需要允许 WebSocket 升级。
- 本机电脑不会开放任何监听端口，连接由 Bosi 主动发起。
- 升级时，请同时部署匹配版本的服务端、Bosi 和 ChatKit。只更新 Bosi 不会让旧的 ChatKit 获得新能力。

## 配置自动化

自动化让助手在指定时间、按计划或事件发生时自动开始工作，并复用助手已发布的指令、技能、工具和连接器。管理自动化需要助手已经发布，并且你拥有工作空间的编辑权限。

1. 将鼠标停在侧栏中的助手头像上，打开助手资料面板，切换到 **自动化**。
2. 新建一个自动化。
3. 选择触发方式：

   | 触发方式 | 何时运行 |
   | --- | --- |
   | 定时计划 | 在指定时间或按计划运行 |
   | 应用事件 | 应用中发生指定事件时运行 |
   | Webhook | 收到 HTTP 请求时运行 |
   | Email | 收到新邮件时运行 |

   定时计划以外的触发方式，需要先在 Xpert 中安装对应类型的 Provider 插件。

4. 设置条件和范围。定时计划可以选择每小时、每天、每个工作日、每周，或者使用自定义计划填写 Cron 表达式（依次为分钟、小时、日期、月份、星期）。定时计划使用 Xpert 服务器的时区。
5. 按需填写补充指令，例如“汇总昨天合并的代码变更和未关闭的问题”。助手的职责、技能、工具和连接器会自动继承，无需重复配置。
6. 确认配置并保存。

保存后，可以在自动化列表中查看最近运行时间，并暂停或启用自动化。每个 Provider 在一个助手上只能配置一个触发器；需要修改时，请编辑已有配置。

## 确认已经可以使用

| 检查内容 | 操作 | 完成标志 |
| --- | --- | --- |
| 本机终端设置 | 在设置中设置测试目录并应用 Shell 设置 | 设置已应用，没有错误提示 |
| 审批流程 | 请求一条本机命令 | 消息中出现审批卡片，批准前命令未执行 |
| 本机执行 | 批准后检查测试目录 | 文件内容与预期一致，退出码为 0 |
| 拒绝流程 | 再请求一条命令并拒绝 | 命令未执行，助手停止这次操作 |
| 自动化 | 创建一个定时计划 | 自动化列表中显示该计划 |

## 常见问题

### 设置中提示桌面 Shell 需要在 macOS 原生应用中使用

本机终端目前只能在 macOS 原生应用中使用。请在 Mac 上安装并登录 Bosi。

### 助手没有请求本机命令

确认管理员已为该助手连接 **Desktop Shell** 中间件并重新发布，模型支持工具调用，并且你提问时明确要求在本机执行。

### 提示本机 Shell 已在权限设置中禁用

执行权限被设置为 **禁止执行**。在 **设置 → 本机终端** 中修改执行权限并应用，再发起新的命令。

### 提示此电脑已离线

Bosi 当前没有连接，命令不会排队等待。确认 Bosi 正在运行并已登录，然后重新请求，不要让助手自动重试。

### 提示命令授权已过期或撤销

审批有有效期，应用 Shell 设置也会撤销尚未执行的授权。请在当前对话中重新请求命令。

### 账号或组织切换后命令无法执行

切换账号或组织会停止本机终端。请在当前对话中重新请求授权。

### 自动化列表中无法新建

确认助手已经发布，并且你拥有工作空间的编辑权限。定时计划以外的触发方式需要先安装对应的 Provider 插件。
