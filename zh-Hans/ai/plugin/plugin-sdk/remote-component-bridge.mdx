# 远程组件宿主桥接

宿主桥接连接远程组件 iframe、工作台宿主和插件视图提供器。它不是任意远程调用通道：业务能力需要清单声明、宿主处理器，以及适用时的服务端实现。通用上下文生命周期事件不需要订阅。

```text
远程组件
  -> postMessage
  -> 工作台宿主
  -> 已认证的视图扩展 API
  -> IXpertViewExtensionProvider
```

远程组件只发送业务意图。宿主负责解析当前用户、宿主、租户和组织上下文，并在调用提供器前校验视图、功能、权限和能力声明。

## 三层能力契约

| 层 | 所有者 | 作用 |
| --- | --- | --- |
| 消息协议 | 宿主与远程组件 | 定义 iframe 请求、响应和生命周期消息 |
| 视图清单 | 插件视图提供器 | 声明允许使用的数据、操作、文件、客户端命令和事件 |
| 提供器方法 | 插件服务端 | 在可信服务端上下文中执行数据查询或业务操作 |

缺少任意一层时，该能力都不应执行。

## 消息信封

所有消息使用固定通道和协议版本：

```ts
interface RemoteMessageEnvelope {
  channel: 'xpertai.remote_component'
  protocolVersion: 1
  instanceId?: string
  type: string
  requestId?: string
  scopeRevision?: number
}
```

- iframe 加载完成后发送 `ready`。
- 宿主使用 `init` 返回 `instanceId`、`runtimeScope`、`scopeRevision`、视图清单、初始查询、语言、主题和调试配置。
- 后续消息必须携带匹配的 `instanceId`。
- 请求与响应使用同一个 `requestId`。
- iframe 只接受 `window.parent` 发出的消息；宿主只接受当前 iframe `contentWindow` 发出的消息。

## 支持的消息

宿主发送给 iframe：

| 消息 | 用途 |
| --- | --- |
| `init` | 初始化清单、查询、语言、主题和调试状态 |
| `hostEvent` | 转发已订阅业务事件或通用 `view.context.changed` 事件 |
| `data` | `requestData` 的响应 |
| `parameterOptions` | 参数选项响应 |
| `actionResult` | JSON 操作响应 |
| `fileActionResult` | 文件操作响应 |
| `fileAccessResult` | 文件预览或下载授权响应 |
| `clientCommandResult` | 客户端命令响应 |
| `error` | 与 `requestId` 对应的请求错误 |

iframe 发送给宿主：

| 消息 | 用途 |
| --- | --- |
| `ready` | 请求初始化 |
| `resize` | 请求调整非固定工作台中的 iframe 高度 |
| `notify` | 请求显示宿主通知 |
| `requestData` | 查询视图数据 |
| `requestParameterOptions` | 查询动态参数选项 |
| `executeAction` | 执行 JSON 操作 |
| `executeFileAction` | 执行文件上传操作 |
| `requestFileAccess` | 请求文件预览或下载授权 |
| `invokeClientCommand` | 请求宿主执行界面操作 |

## 能力映射

| 能力 | 清单声明 | iframe 消息 | 服务端处理 |
| --- | --- | --- | --- |
| 数据查询 | `dataSource` | `requestData` | `getViewData` |
| 参数选项 | `parameters[].optionSource` | `requestParameterOptions` | `getViewParameterOptions` |
| JSON 操作 | `actions[].transport = 'json'` | `executeAction` | `executeViewAction` |
| 文件操作 | `actions[].transport = 'file'` | `executeFileAction` | `executeViewFileAction` |
| 文件访问 | `fileAccess.purposes` | `requestFileAccess` | `resolveViewFile` |
| 客户端命令 | `clientCommands[]` | `invokeClientCommand` | 宿主命令注册表 |
| 宿主事件 | `hostEvents.subscriptions[]` | `hostEvent` | 宿主管理 |
| 远程入口 | `view.type = 'remote_component'` | 宿主管理 | `getRemoteComponentEntry` |

## 切换上下文而不重建 iframe

同一认证身份、组织和助手下切换项目或会话时，iframe 保持不变。宿主重新授权目标 View 和入口，在解析期间暂停操作；完成后向所有已挂载 View（包括隐藏页签）发送 `view.context.changed`，无需清单订阅或确认握手。

`init.runtimeScope` 与事件中的 `data.runtimeScope` 都是完整快照。未绑定字段为 `null`，应整体替换，不能合并旧 ID。当前 Angular 宿主提供项目与会话字段，支持分组路由的宿主还可提供 `groupId`。

```json
{
  "channel": "xpertai.remote_component",
  "protocolVersion": 1,
  "instanceId": "view-instance",
  "type": "hostEvent",
  "event": {
    "id": "context-change-2",
    "type": "view.context.changed",
    "source": "chatkit",
    "receivedAt": "2026-11-09T00:00:00.000Z",
    "data": {
      "revision": 2,
      "runtimeScope": { "projectId": null, "conversationId": "target-conversation" }
    }
  }
}
```

revision 在同一实例内单调增加，但不保证连续。忽略过期修订，拒绝旧待处理请求，清空选择，并在新作用域刷新或重新绑定。后续每次请求携带最新 `scopeRevision`。宿主使用自己的授权上下文，不接受请求指定身份范围，并随上下文轮换文件会话。

更换身份、组织、助手或入口，显式重新加载或关闭 View 会销毁旧实例。入口访问被拒绝时，旧文档也必须移除。取消请求或丢弃响应不会撤销已经提交的服务端修改。

## TypeScript 桥接客户端

桥接集中在 `bridge.ts`，业务组件不直接拼装协议消息。以下示例面向支持上下文修订的宿主，每个 iframe 只安装一次桥接。业务包装函数在使用结果前仍需校验返回载荷。

```ts
const CHANNEL = 'xpertai.remote_component'
const VERSION = 1
const responses = {
  requestData: 'data',
  requestParameterOptions: 'parameterOptions',
  executeAction: 'actionResult',
  executeFileAction: 'fileActionResult',
  requestFileAccess: 'fileAccessResult',
  invokeClientCommand: 'clientCommandResult'
} as const

type RequestType = keyof typeof responses
type RuntimeScope = {
  groupId: string | null
  projectId: string | null
  conversationId: string | null
}
interface BridgeMessage {
  channel: typeof CHANNEL
  protocolVersion: typeof VERSION
  type: string
  instanceId?: unknown
  scopeRevision?: unknown
  runtimeScope?: unknown
  requestId?: unknown
  event?: unknown
  message?: unknown
  data?: unknown
  result?: unknown
}
interface PendingRequest {
  revision: number
  responseType: string
  resolve(value: unknown): void
  reject(error: Error): void
  timeout: number
}

let instanceId: string | null = null
let revision: number | null = null
let sequence = 0
const pending = new Map<string, PendingRequest>()
export const currentScopeRevision = () => revision

export function installBridge(handlers: {
  onInit(message: BridgeMessage): void
  onContextChange(scope: RuntimeScope, revision: number): void
  onHostEvent(event: unknown): void
}) {
  const listener = (event: MessageEvent<unknown>) => {
    if (event.source !== window.parent || !isBridgeMessage(event.data)) return
    const message = event.data
    if (message.type === 'init') {
      const scope = parseScope(message.runtimeScope)
      if (typeof message.instanceId !== 'string' || !scope ||
          !isRevision(message.scopeRevision)) return
      if (instanceId && message.instanceId !== instanceId) return
      if (revision !== null && message.scopeRevision < revision) return
      if (revision !== message.scopeRevision) rejectPending('view_context_changed')
      instanceId = message.instanceId
      revision = message.scopeRevision
      handlers.onInit(message)
      return
    }
    if (!instanceId || message.instanceId !== instanceId) return
    if (message.type === 'hostEvent') {
      const change = parseContextChange(message.event)
      if (change) {
        if (revision !== null && change.revision <= revision) return
        rejectPending('view_context_changed')
        revision = change.revision
        handlers.onContextChange(change.scope, revision)
        return
      }
      handlers.onHostEvent(message.event)
      return
    }
    if (typeof message.requestId !== 'string') return
    const request = pending.get(message.requestId)
    if (!request || request.revision !== revision) return
    if (message.scopeRevision !== undefined && message.scopeRevision !== revision) return
    if (message.type !== 'error' && message.type !== request.responseType) return
    pending.delete(message.requestId)
    window.clearTimeout(request.timeout)
    if (message.type === 'error') {
      request.reject(new Error(typeof message.message === 'string'
        ? message.message : 'remote_request_failed'))
    } else {
      request.resolve(message.data ?? message.result)
    }
  }
  window.addEventListener('message', listener)
  window.parent.postMessage({ channel: CHANNEL, protocolVersion: VERSION, type: 'ready' }, '*')
  return () => {
    window.removeEventListener('message', listener)
    rejectPending('remote_bridge_disposed')
    instanceId = null
    revision = null
  }
}

export function requestHost(type: RequestType, body: object) {
  const requestRevision = revision
  if (!instanceId || requestRevision === null) {
    return Promise.reject(new Error('remote_bridge_not_initialized'))
  }
  const requestId = `${Date.now()}-${++sequence}`
  return new Promise<unknown>((resolve, reject) => {
    const timeout = window.setTimeout(() => {
      pending.delete(requestId)
      reject(new Error('remote_request_timeout'))
    }, 30_000)
    pending.set(requestId, {
      revision: requestRevision, responseType: responses[type], resolve, reject, timeout
    })
    try {
      window.parent.postMessage({
        ...body, channel: CHANNEL, protocolVersion: VERSION,
        instanceId, scopeRevision: requestRevision, type, requestId
      }, '*')
    } catch {
      pending.delete(requestId)
      window.clearTimeout(timeout)
      reject(new Error('remote_request_not_cloneable'))
    }
  })
}

function rejectPending(code: string) {
  for (const request of pending.values()) {
    window.clearTimeout(request.timeout)
    request.reject(new Error(code))
  }
  pending.clear()
}
function isRevision(value: unknown): value is number {
  return typeof value === 'number' && Number.isSafeInteger(value) && value >= 0
}
function isId(value: unknown): value is string | null {
  return value === null || typeof value === 'string'
}
function parseScope(value: unknown): RuntimeScope | null {
  if (!value || typeof value !== 'object' ||
      !('projectId' in value) || !isId(value.projectId) ||
      !('conversationId' in value) || !isId(value.conversationId)) return null
  const groupId = 'groupId' in value ? value.groupId : null
  if (!isId(groupId)) return null
  return { groupId, projectId: value.projectId, conversationId: value.conversationId }
}
function parseContextChange(value: unknown) {
  if (!value || typeof value !== 'object' || !('type' in value) ||
      value.type !== 'view.context.changed' || !('data' in value)) return null
  const data = value.data
  if (!data || typeof data !== 'object' || !('revision' in data) ||
      !isRevision(data.revision) || !('runtimeScope' in data)) return null
  const scope = parseScope(data.runtimeScope)
  return scope ? { revision: data.revision, scope } : null
}
function isBridgeMessage(value: unknown): value is BridgeMessage {
  return !!value && typeof value === 'object' && !Array.isArray(value) &&
    'channel' in value && value.channel === CHANNEL &&
    'protocolVersion' in value && value.protocolVersion === VERSION &&
    'type' in value && typeof value.type === 'string'
}
```

业务代码可以在此基础上封装 `requestData()`、`executeAction()` 和 `invokeClientCommand()` 等具名方法。桥接层返回稳定错误代码，由 UI 多语言层转换成用户可见文案。

在 `onContextChange` 中先清空依赖作用域的状态，再刷新或重新绑定。响应后的异步处理也应保存 `currentScopeRevision()`，在写入结果前再次比较。相同修订的重复 `init` 可更新主题/语言，不应重置所选资源。

## 查询数据

```ts
const result = await requestHost('requestData', {
  query: {
    page: 1,
    pageSize: 20,
    search,
    parameters: {
      table: 'contracts',
      status
    }
  }
})
```

`XpertViewQuery.parameters` 只支持标量或标量数组。复杂筛选条件应序列化为明确的 JSON 字符串参数，并由提供器安全解析。

大型表格应使用服务端分页。远程组件不要一次把所有记录加载到 iframe。

## 执行操作

普通业务变更使用 JSON 操作：

```ts
await requestHost('executeAction', {
  actionKey: 'approve_contract',
  targetId: contractId,
  input: { comment },
  parameters: { projectId }
})
```

`actionKey` 必须存在于 `manifest.actions`，且传输方式必须匹配。提供器仍需校验目标对象、当前用户和租户/组织范围。

文件上传使用 `executeFileAction`，不要把二进制内容或 Base64 放进 JSON 操作。文件预览与下载使用 `requestFileAccess`，由宿主换取有时效的访问授权。

## 客户端命令

客户端命令用于宿主本地 UI 行为，不调用插件提供器。例如发送 Assistant 消息、设置 Assistant 上下文、打开文件或导航到另一工作台视图。

它是一个封闭的三方契约：

1. 源视图在 `manifest.clientCommands` 中声明命令键。
2. 当前宿主注册同名处理器。
3. 远程组件通过 `invokeClientCommand` 调用，并处理结构化失败结果。

```ts
import {
  WORKBENCH_NAVIGATION_OPEN_COMMAND,
  WORKBENCH_EXTENSION_VIEW_TARGET
} from '@xpert-ai/contracts'

await requestHost('invokeClientCommand', {
  commandKey: WORKBENCH_NAVIGATION_OPEN_COMMAND,
  payload: {
    target: WORKBENCH_EXTENSION_VIEW_TARGET,
    viewKey: 'contract_review__history',
    selectionId: contractId
  }
})
```

不要从 iframe 直接修改顶层窗口地址。

### 当前宿主命令

| 命令 | 输入与行为 |
| --- | --- |
| `workspace.connector.connect` | `{ provider, authMethodId?, integrationId? }`；打开已授权的连接配置。选择具体 integration 时还需对应认证方法，成功数据返回 `connected` 或 `cancelled`，不返回凭据。 |
| `workbench.content.resolve` | `{ resourceId, providerKey }`；解析有权访问的内容编辑器，将返回的 `navigation` 原样传给 `workbench.navigation.open`。 |
| `artifact.presentation.open` | `{ url: presentationUrl }`；打开平台认证产物展示页，仅接受平台 `/artifacts/view/:slug` URL。 |

声明实际使用的命令，检查结构化结果，并展示处理器不可用或弹窗拦截。清单声明不代表每个宿主都实现了命令。不能在载荷中添加租户/工作区身份或凭据。

## 宿主事件

远程组件可以订阅宿主归一化后的事件，例如 Agent 中间件工具完成：

```ts
hostEvents: {
  subscriptions: [
    {
      key: 'contract-mutated',
      event: 'assistant.tool.completed',
      filter: {
        sources: ['chatkit'],
        toolNames: ['contract_update', 'contract_approve']
      },
      action: { type: 'forward', debounceMs: 800 }
    }
  ]
}
```

声明式视图通常使用 `refresh`。远程组件优先使用 `forward`，根据业务 ID 只刷新受影响的数据区域，并在本地存在未保存编辑时避免静默覆盖。

## 初始化、主题和多语言

以 `init.locale` 为准，在入口处一次性归一化为 BCP 47 语言标签，例如 `en-US`、`zh-Hans` 和 `zh-Hant`。不要在业务组件中根据语言直接选择文本。

应用 `init.theme.tokens` 后，调用 `installShadcnThemeVars()` 安装语义主题变量。调试日志由 `init.debug.enabled` 控制；不要根据 URL、主机名或平台身份猜测开发环境。

不要依赖 `localStorage` 或 `sessionStorage`。临时状态保存在 React 状态中，持久状态通过宿主桥接写入服务端。

## 安全检查

- 不向 iframe 传递访问令牌、API 地址、Assistant ID、租户 ID 或组织 ID。
- 不让 iframe 自行选择 `hostType` 或 `hostId`。
- 不执行清单未声明的操作、文件能力或客户端命令。
- 不在日志中输出令牌、文件内容、完整业务快照或个人敏感信息。
- 提供器对每次读取和变更重新执行授权与租户/组织隔离。
- 对消息来源、协议版本、实例 ID 和请求 ID 添加自动化测试。
