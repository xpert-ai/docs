Bosi 可以把对话与实际执行连接起来。先明确工作应在哪里发生，再确认助手具备对应能力；安装 Bosi 并不会自动把本机文件同步到云端，也不会自动提供所有执行环境。

## 选择执行位置

| 方式 | 工作位置 | 常见用途 | 前提 |
| --- | --- | --- | --- |
| 本机 Shell | 当前 Mac | 检查本机目录、运行构建和测试命令 | 原生 macOS Bosi、助手 Desktop Shell 能力及本机执行授权 |
| 服务端沙箱 | Xpert 服务端隔离环境 | 文件处理、代码和命令执行 | 部署了相应沙箱与工具 |
| 云电脑 | 服务端远程桌面 | 操作浏览器或桌面应用，使用编程工具 | 服务端提供云电脑能力，助手及模型符合要求 |

当前本机 Shell 属于 macOS 原生应用的预览能力。Windows、Linux 或浏览器中的 Bosi 相关界面不能据此被视为支持本机命令。云电脑实现由 Pro 提供，实际入口以所连接部署为准。

## 使用本机 Shell

1. 确认助手已启用并发布 Desktop Shell 能力；首次创建个人 Bosi 时也可按可用选项启用。
2. 在**设置 → 本机终端**核对电脑名称、Shell 和默认工作目录；修改后点击**应用 Shell 设置**。
3. 明确告诉助手需要在本机执行什么。默认策略下，对话显示命令、电脑和工作目录，等待你批准一次或拒绝。
4. 执行后核对输出、退出码和实际文件；需要中止时，在本机终端的近期命令中停止。

执行权限可以选择**每条命令先询问**、**始终允许此组织的命令**或**禁止执行**，只作用于当前服务、账号、组织和这台设备。始终允许会跳过后续逐条询问；禁止执行会停止正在运行的命令。

本机命令以当前操作系统用户权限执行，工作目录只是起始位置，不是文件隔离范围。输出会返回 Xpert 服务。每条命令使用新的非交互 Shell，不提供持续终端会话或交互输入。

当前每台设备同时执行一条命令；离线时不会排队，也不会自动换到服务端沙箱。显示“未知”时，应先核对原执行结果，不能把它理解为尚未执行。关闭 macOS 窗口会保留仍在运行的应用；退出应用、退出登录或切换组织会停止本机执行连接。

## 查看和接管云电脑

在可用助手的 Workbench 中打开**电脑**，连接查看远程桌面。需要键盘和鼠标输入时选择**开始操作**，仅观察时选择**仅查看**。

这是你与 Agent 共享的远程桌面。退出接管或断开查看不等于停止其中的任务，也不会自动删除文件。停止运行应使用对应任务或编程会话的控制入口。

首次向导中的电脑插图只用于介绍能力，不能作为云电脑已创建或已连接的依据。

## 在云电脑中使用编程工具

云电脑面板中的**编程工具**展示当前会话可用的 CLI。先检查安装状态、模型兼容性和运行方式，再打开工具。具体工具名单由部署提供。

| 标记 | 判断方法 |
| --- | --- |
| 已安装与模型兼容 | 同时满足后，才具备打开该工具的基本条件 |
| 支持受管任务 | 可接入已支持的受管后台任务流程 |
| 仅交互运行 | 不应当作支持受管后台任务 |
| 运行中、已退出或状态未知 | 查看实际会话状态，不能按是否仍在接管桌面判断 |

交互编程工具使用当前会话可用的模型。项目会话通常以项目文件根目录工作，与项目中的其他助手共享文件；应协调并发修改。关闭接管不会自动终止编程会话，需要结束时使用**停止**。
