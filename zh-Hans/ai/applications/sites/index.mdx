**Sites** 将网站制作、版本预览和发布放在同一个 Xpert 工作流程中。向站点构建助手描述需求，在左侧对话中持续修改，在右侧工作台检查页面，确认后获得可以访问和分享的站点链接。

它适合产品介绍页、活动页面、入职与团队资源门户、报告和交互式说明，以及基于已提供数据的展示看板。

## 核心能力

| 能力 | 可以完成的工作 |
| --- | --- |
| 对话构建 | 根据需求、文件和说明生成页面内容、样式与浏览器交互，继续用自然语言修改 |
| 站点工作台 | 管理站点，预览已保存版本，切换桌面和手机宽度检查布局 |
| 版本管理 | 保存内容快照，查看历史，将旧版本恢复为新草稿后继续处理 |
| 受控发布 | 明确选择要发布的版本和访问范围，通过 Xpert Artifacts 生成访问链接 |
| 分享管理 | 限定访问者或确认公开，必要时撤销链接 |

## 开始使用

由管理员完成[应用启用与授权](/zh-Hans/ai/applications/app-guide/discovery-and-setup)，配置可用的主模型、平台沙箱及 Artifacts 能力。打开 Sites 站点构建助手后：

1. **新建站点。** 在工作台点击**新建站点**，填写名称与需求，说明受众、内容、视觉风格和需要的交互。
2. **生成并保存。** 助手在当前对话中生成站点文件并保存可审阅版本；提供真实资料，可让页面内容更贴合业务。
3. **预览和修改。** 检查桌面与手机预览，使用**在对话中继续修改**提出调整，再查看新保存的版本。
4. **确认发布。** 点击**发布版本**，核对选定版本与访问范围。发布后打开实际站点检查内容及交互。
5. **分享和更新。** 将发布链接提供给对应访问者。后续修改先保存新版本，确认后再发布。

例如：

> 为团队制作一个新员工入职门户，使用我提供的资料，包含第一周安排、常用资源和可展开的问题解答。先保存一个适配手机的版本供我预览。

## 版本与发布

**站点项目**集中管理源文件和历史，**保存版本**记录一次确定的内容，**发布**决定访问者当前能看到的版本。保存或恢复草稿不会自动替换已发布站点。

需要回到旧内容时，在**版本**中选择历史记录并点击**恢复为新草稿**。检查后重新发布，访问者才会看到这次变更。

## 访问范围

| 选项 | 适用场景 |
| --- | --- |
| 仅自己 | 个人预览和早期检查 |
| 工作区成员 | 面向当前工作空间成员的内部站点 |
| 指定用户 | 仅向明确选择的用户开放 |
| 任何持链接的人 | 确认后公开，获得链接的人可以访问 |

公开发布需要明确确认，分享的是生成的站点内容。原始对话与工作空间不会随站点一起公开。撤销链接会使对应访问入口失效，项目与保存版本仍可保留；链接机制详见 [Artifacts](/zh-Hans/ai/agent/artifacts/index)。

## 适用范围

当前发布的是自包含的静态单页站点，支持打包页面样式、脚本、图片与字体，以及浏览器内的交互。页面在隔离环境中运行，交互状态保存在内存中。

需要服务端接口、数据库、用户登录、长期保存表单数据或实时拉取外部数据的业务，超出当前托管范围。发布页不能调用网络 API 或使用浏览器持久存储，当前也不提供自定义域名与真实流量统计。制作看板或表单时，应按静态展示和本次页面内交互来设计。
