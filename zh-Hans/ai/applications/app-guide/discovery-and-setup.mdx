在 Bosi 的**发现与添加 → 应用**中，可以按业务需求查找当前范围内可用的应用。启用前先查看详情，明确应用用途、所需配置与使用后的入口。

## 阅读应用详情

应用的说明与截图帮助你了解业务体验；“应用包含”展示其实际声明的入口 Assistant、协作或独立角色、工作空间和知识资源。多角色应用可以提供不同的专业分工，并按其配置组织协作。

详情中的初始化检查会说明当前缺少什么。先核对组织和权限，再处理模型、工具提供方与配置要求。如果目录中没有目标应用，由管理员检查插件是否已安装、实际加载并在当前范围可用。

## 准备模型与工具

| 准备项 | 操作 |
| --- | --- |
| 主模型 | 确保组织中有应用可使用的模型配置 |
| 向量、视觉或语音识别模型 | 应用有相应要求时，按向导选择适合用途的模型 |
| 必需工具集 | 为每项需求选择可用配置；没有合适配置时通过“新增配置”完成授权与设置 |
| 外部账号与数据 | 按服务要求授权，并确认目标用户对相关业务数据有访问权限 |

模型和工具要求由各应用声明，并非每款应用都需要所有选项。安装工具提供方插件后，仍需配置可实际调用的工具实例。

通过向导新增工具配置时，平台会先准备应用专用工作空间，保存配置供后续启用使用。选择其他工作空间的来源配置时，启用过程会为应用创建独立副本；后续修改来源不会自动更新该副本，来源依赖的环境变量或其他资源也不会随之复制。

## 初始化到当前组织

1. 确认当前组织以及应用详情中的启用条件。
2. 完成必需模型和工具配置，核对应用将创建的资源。
3. 提交初始化，等待平台创建或复用专用工作空间、知识资源与 Assistant。
4. 状态就绪后，进入应用的已发布入口 Assistant。
5. 为其他员工分配使用权限，再进行应用自身要求的业务配置和首次任务。

当前应用初始化创建组织内的私有工作空间，初始化者负责维护。初始化不会自动把全组织员工加入该空间或授予 Assistant 使用权。操作见[权限与应用维护](./access-and-updates)。

## 理解配置与运行状态

| 状态 | 含义与下一步 |
| --- | --- |
| 尚未启用 | 完成准备并初始化 |
| 待配置 | 已准备应用配置资源，继续完成要求并启用 |
| 初始化中 | 正在准备资源，等待并刷新状态 |
| 已就绪 | 资源初始化已完成，可由获授权用户进入应用 |
| 失败或需要修复 | 查看具体原因，处理后从同一应用入口重试或修复 |

同一组织内重复初始化会复用同一应用的安装记录和仍有效的资源。关闭向导会保留已保存的工具配置，重新进入后可以继续；仅查看详情或打开向导不会创建资源。

尚未启用且满足清理条件时，管理员可以使用**放弃配置**清理准备阶段的工作空间和工具集。已启用、初始化中或已增加其他资源的空间不适用此操作。遇到失败时，优先检查原因并继续原有配置，详见[常见问题](./troubleshooting)。
