应用在组织中启用后，管理员需要明确谁可以使用、谁负责维护，以及哪些业务数据可以访问。日常使用者通常从已发布 Assistant 进入应用；维护人员负责工作空间中的配置和资源。

## 分配使用与维护职责

| 角色 | 主要工作 |
| --- | --- |
| 平台或组织管理员 | 按插件要求安装能力，准备模型与连接，完成获准的应用初始化 |
| 应用维护人员 | 维护应用工作空间、Assistant 配置及配套资源 |
| 业务使用者 | 使用已获授权的 Assistant，处理自己可访问的业务对象 |
| 业务复核人员 | 按应用规则检查结果并完成相应确认 |

这里描述的是工作职责；实际操作仍按平台角色、空间成员关系及应用自己的权限检查执行。

当前宿主初始化应用时创建专用私有工作空间，初始化者成为所有者。为员工开放使用时，由具备相应权限的管理员：

1. 切换到应用所在组织。
2. 在**设置 → 用户组**中选择或创建使用者组，并添加员工。
3. 为该组分配应用已发布 Assistant 的使用权限。
4. 让员工刷新应用入口并尝试一次符合其权限的业务操作。

需要修改 Assistant 或空间资源的人员，由空间所有者另外加入维护成员。详细授权路径与撤销规则见 [Assistant 与应用授权](/zh-Hans/ai/system/permissions/assistant-application-authorization)。

## 业务数据继续独立授权

能使用入口 Assistant，表示具备这条使用路径。项目成员关系、应用业务对象、知识库、文件和外部服务仍按各自规则判断访问范围。

排查访问问题时先核对当前服务、账号、组织与目标对象，再检查相应资源权限。多个角色协作时，也需要确认应用实际调用的资源已经正确配置。应用详情中的数据范围说明帮助用户理解用途，实际访问由服务端执行。

## 区分维护与升级操作

| 操作 | 影响 |
| --- | --- |
| 更新插件包 | 更新平台加载的实现和可提供的模板资源 |
| 初始化或修复应用 | 创建或补齐该组织应用缺失的受管资源，复用仍有效的资源 |
| 升级 Assistant 模板 | 按适用的模板升级流程检查差异、处理本地修改并发布 |
| 修改工具配置 | 影响该配置后续调用；应用中的副本需单独维护 |
| 迁移业务数据 | 按应用提供的迁移说明处理已有业务记录 |

插件刷新成功不代表已有 Assistant 已采用新模板；应用已就绪也不代表完成业务数据迁移。维护人员应按应用发布说明逐项执行，并通过实际业务任务核对结果。

模板实例的升级方式见[智能体模板使用指南](/zh-Hans/ai/agent/conversation/assistant-templates)。开发和部署人员可进一步阅读[应用初始化配置](/zh-Hans/ai/plugin/application-config)。

## 保留已有配置与数据

重复初始化或修复会保留仍然存在的工作空间成员与可见性设置。旧应用的共享范围需要由所有者显式调整；升级宿主不会自动改变既有空间的维护范围。

停用插件、撤销员工使用权和删除业务数据是不同操作。应用数据的归档、迁移和清理由其产品流程决定；准备阶段的“放弃配置”只适用于满足条件的未启用配置。执行清理前应按该应用说明确认具体对象与影响。
