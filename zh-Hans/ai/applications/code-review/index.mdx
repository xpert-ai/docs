**Code Review** 帮助开发者和代码维护者在 Xpert 中完成 GitHub Pull Request 审查。左侧对话用于说明审查重点、追问问题，右侧工作台展示文件差异、检查结果和 AI 发现，让每条意见都能回到具体提交版本和代码位置核对。

## 核心能力

| 能力 | 可以完成的工作 |
| --- | --- |
| PR 收件箱 | 打开公开 PR 地址，连接 GitHub 后查看等待自己审查或自己创建的 PR，保留最近与置顶记录 |
| 代码与依据 | 浏览固定提交版本的差异，标记文件已阅，查看 GitHub 检查结果及审查覆盖范围 |
| AI 审查 | 指定审查重点，在后台分析变更；按优先级查看问题、触发条件、影响和代码位置 |
| 对话追问 | 从具体发现进入当前对话，结合源码继续解释与核实 |
| 提交审查 | 选择要提交的问题和结论，核对后以已连接的 GitHub 账号提交 |
| 仓库自动审查 | 按 PR 事件、目标分支和忽略路径安排审查，在收件箱处理待确认、已发布及失败记录 |

## 开始使用

由管理员完成[应用启用与授权](/zh-Hans/ai/applications/app-guide/discovery-and-setup)，为代码审查助手配置可用的主模型。公开 PR 可直接读取；私有仓库和提交审查需要在当前工作空间连接具有相应权限的 GitHub 账号。

1. **打开 PR。** 在 Code Review 中输入 GitHub PR 地址，选择公开或已连接的访问方式；也可从 PR 列表进入。
2. **检查变更。** 浏览概览、文件变更与检查结果，确认本次提交和可读取的范围。
3. **发起审查。** 填写审查重点，点击**审查变更**。完成后查看审查结论和问题列表。
4. **核实发现。** 对照差异与源码检查问题，必要时点击**在对话中询问**继续追问。结果先保存在 Xpert，供你复核。
5. **确认提交。** 点击**提交审查**，选择问题、编辑说明，并选择**仅评论、批准或请求修改**，核对后提交到 GitHub。

例如，可以把审查重点设为：

> 重点检查权限校验和并发更新。请说明问题的触发条件、实际影响及对应代码位置，并指出未能覆盖的部分。

## 按仓库开启自动审查

自动审查需要管理员配置 GitHub App 和可接收事件的回调，并将 App 安装到目标仓库。配置人还需连接 GitHub，具备该仓库的写入或管理权限。

在**仓库**中添加目标仓库，进入**配置规则**，先用一个现有的开放 PR 试审，再启用规则。可以设置触发事件、目标分支、忽略路径、审查重点和每日额度；试审会消耗模型用量，结果保持私有。

| 交付方式 | 行为 |
| --- | --- |
| 保存待确认结果 | 默认方式；自动完成审查后，在收件箱核对并确认发布 |
| 自动评论 | 启用后以 GitHub App 身份发布摘要及 P0/P1 行内问题，完整结果保留在 Xpert |

自动审查默认暂停，跳过草稿 PR 和机器人创建的 PR；可按需调整机器人与事件规则。自动发布只使用评论，不会批准、请求修改或合并 PR。可以随时暂停规则，历史记录仍保留。

## 结果与异常处理

- **PR 有新提交**：刷新并重新审查，旧版本上的结论不能直接作为新提交的审查结果发送。
- **覆盖范围不完整**：二进制、大文件差异或检查记录可能无法读取，应按界面提示补充检查；应用展示已有检查结果，AI 审查本身不代表运行过测试。
- **需核实提交**：网络异常可能导致无法确认 GitHub 是否已收到审查，先打开 PR 核实，再决定下一步，避免重复发送。

审查草稿按用户与助手隔离；GitHub 凭据由平台连接器管理。日常使用与权限维护参见[应用使用指南](/zh-Hans/ai/applications/app-guide/access-and-updates)。
