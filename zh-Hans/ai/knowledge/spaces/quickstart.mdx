---
title: "创建第一份协作页面"
description: "启用空间能力，选择项目，创建并保存一份可再次打开的团队页面。"
---

本例创建一份“项目操作手册”，验证页面能够保存、重新打开，并供项目中的 Assistant 使用。

## 使用前准备

管理员安装兼容的 Spaces 与 Markdown 编辑器插件并完成要求的服务重启。为 Assistant 选择支持工具调用的可用模型，在创建时的 **Assistant 能力** 或已有 Assistant 的 **设置 → 能力** 中启用 **协作空间**，然后发布。

启用能力只配置 Assistant，不会自动创建项目或授予项目权限。

## 1. 选择项目并打开空间

创建或选择类型为“协作空间”的项目，将该 Assistant 连接到项目，并给协作者分配适当角色。

展开左侧 Assistant 菜单，选择 **协作空间**。如果提示选择项目，选择已有的协作空间项目，或通过 **新建项目 · 协作空间** 创建项目。已经在项目对话中时，也可以点击右上角的 **打开视图**，再选择 **协作空间** 标签。

如果入口缺失，检查插件是否已加载、Assistant 是否已发布并启用空间能力，以及当前项目绑定和成员权限。

## 2. 创建页面

选择 **新建 → 页面**，在弹窗中切换到 **空白页面**，填写页面名称“项目操作手册”，确认存放位置后点击 **创建页面**。编辑器会自动打开；也可以先选择项目简报、会议纪要或团队周报模板。

在空白页面中输入：

```markdown
# 项目操作手册

## 目标
记录团队启动项目时需要准备的材料。

## 启动检查
- [ ] 确认项目成员
- [ ] 整理输入资料
- [ ] 确认交付要求
```

编辑时会显示“正在保存…”，完成后显示 **已保存到项目文件**。看到保存完成后，再关闭并重新打开页面检查内容。保存失败时保留当前编辑器并处理提示，不要将关闭窗口当作保存。

## 3. 与 Assistant 继续完善

点击编辑器顶部的 **在 Assistant 中审阅**，在 **让 Assistant 协助** 中输入：“为启动检查补充每项的完成标准，先给出修改建议。”点击 **发送给 Assistant**。提案生成后，再打开审阅面板，对比原文与建议，选择 **接受修改** 或 **拒绝**。接受后回到页面，确认正文更新并显示保存完成。详见[与 Assistant 共同写作](./assistant-writing)。

## 4. 检查结果

- 重新打开页面，标题、正文和检查清单仍然存在。
- 有编辑权限的成员能在同一页面协作；只读成员能查看但不能修改。
- 另一位已绑定此项目的 Assistant 使用同一份内容。
- 如果需要正文问答，继续[启用知识检索](./search-and-reuse)并等待索引完成。

这份页面可以继续在项目中维护。项目归档后，内容转为只读。
