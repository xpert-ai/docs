Xpert Tag 的价值在于把数字专家放进团队已经工作的群里。以下场景按当前 Xpert 能力和后续产品目标组织，便于试点和规划。

## 场景矩阵

| 场景 | 用户 | 需要的能力 | 状态 |
| --- | --- | --- | --- |
| 请求分流 | IT、法务、设计、行政、支持团队 | 群聊 @、知识库、工单工具、群规则。 | 部分实现 |
| 群总结和追踪 | 项目经理、团队负责人 | 群消息上下文、摘要、待办识别、Schedule Trigger。 | 部分实现 |
| 文档和工单生成 | 产品、交付、支持 | 群讨论摘要、文档模板、工单/文档工具。 | 部分实现 |
| 项目状态 | PM、交付、客户成功 | 项目群上下文、工单、审批、日程、日报 routine。 | 部分实现 |
| 数据问答 | 业务、运营、数据团队 | BI 工具集、语义模型、只读数据连接、图表输出。 | 部分实现 |
| 知识库检索 | 全员 | 知识库、文档源、引用和来源。 | 已实现基础能力 |
| 文档审查 | 合规、采购、售前、法务 | 文件输入、知识库、检查清单、审查报告。 | 部分实现 |
| 销售状态 | 销售、客户成功 | CRM、通话记录、商机、客户知识库。 | 未实现（规划） |
| 监控告警 | SRE、运维、研发 | 监控/日志/工单工具、群 watch、定时检查。 | 未实现（规划） |
| Bug 和 GitHub | 研发、测试、产品 | Coding Expert、代码平台、CI、PR 跟踪。 | 部分实现 |

## 请求分流

适用于 `#ask-it`、设计支持群、法务咨询群、客户支持群。

示例：

```text
@Xpert 这个问题是否已有处理流程？如果有请直接回答；如果没有，请整理成工单草稿并建议负责人。
```

当前可用：

- 群聊 @ 和单聊触发。
- 知识库问答。
- 工单工具或自定义工作流。
- 消息汇总窗口。

未实现（规划）：

- 群级记忆保存“如何分流请求”。
- 群消息 watch 自动发现未处理请求。
- 统一的重复请求识别和每周主题汇总。

## 群总结和追踪

适用于项目群、发布群、客户交付群。

示例：

```text
@Xpert 总结本周这个群的关键进展、风险、阻塞和待办，按负责人分组。
```

当前可用：

- [飞书](../plugin/integration/lark-integration) 消息历史与资源读取能力。
- 触发器会话上下文。
- Schedule Trigger 定时运行。
- 文本或卡片返回结果。

部分实现：

- 不同 IM 的群历史读取能力不完全一致。
- live checklist 和统一进度展示尚未统一。

未实现（规划）：

- 群级 routine 管理。
- 群记忆中的日报格式和项目规则。

## 文档和工单生成

适用于需求讨论、客户反馈、事故复盘、会议纪要。

示例：

```text
@Xpert 把这个讨论整理成一页 PRD：背景、目标用户、需求范围、非目标、验收标准和待确认问题。
```

当前可用：

- 数字专家生成结构化文档草稿。
- 知识库、工具集和模板能力。
- 部分平台支持文件、卡片或链接输出。

未实现（规划）：

- Tag artifact 管理页。
- 从群内一键转工单、转文档、转审批的统一按钮。
- 输出 artifact 与 Tag session 的统一审计。

## 数据问答

适用于运营群、经营分析群、销售管理群。

示例：

```text
@Xpert 查一下本周各区域新增线索和转化率，生成图表并指出异常变化。
```

当前可用：

- BI 工具集、ChatBI、语义模型和指标管理能力。
- 数字专家可调用工具生成分析结论。

部分实现：

- 在 IM 群里稳定返回图表和文件依平台能力不同。
- 群级只读数据 Access Bundle 尚未产品化。

## 知识库检索

适用于制度问答、产品手册、实施手册、售前资料。

示例：

```text
@Xpert 我们现在的采购审批额度规则是什么？请给出处。
```

当前可用：

- 知识库检索。
- [飞书](../plugin/integration/lark-integration) 文档源等文档接入能力。
- 数字专家可按来源回答。

建议：

- 在试点群中先接入只读知识库。
- 要求回答包含来源或引用。
- 把稳定规则沉淀为技能或群记忆。

## 监控告警

适用于 SRE、运维和研发排障群。

示例：

```text
@Xpert 调查这个告警，从最近部署、错误日志和指标趋势中找可能原因，只给诊断，不要自动改代码。
```

当前可用：

- 可通过工具集或自定义插件接入监控、日志、工单。
- 数字专家可以生成排障步骤和摘要。

未实现（规划）：

- 群 watch 自动触发告警分析。
- 监控系统 Access Bundle。
- 默认拒绝出站网络和凭证代理。
- 告警 routine 的状态管理。

## Bug 和 GitHub

适用于研发群、测试反馈群、代码审查群。

示例：

```text
@Xpert 在 acme/data-pipeline 中检查这个 bug 是否存在。如果是 bug，请给出修复方案并准备 PR 草稿；如果不是，请解释当前代码行为。
```

当前可用：

- [Coding Expert](../agent/toolset/coding-expert) 支持主流代码平台连接和 PR/Issue 相关能力。
- 虚拟环境、Git 工具和代码执行工具可支持代码分析。

部分实现：

- 从 IM 群聊触发代码平台完整任务需要按数字专家和工具集配置组合。
- “开 PR、跟踪 CI、回群更新”的完整 Tag 流程尚未统一。

未实现（规划）：

- 群级 GitHub 仓库授权。
- PR follow routine。
- 每个 PR 与 Tag session 的双向链接和统一审计。
