---
title: 本体理论
description: 说明实体、关系、属性、动作、策略与执行约束如何组成可治理的业务语义。
---

本体理论把业务世界表达为可识别、可关联、可校验的对象空间。它不仅描述实体、关系和属性，也描述对象可以执行的动作、动作的治理策略，以及执行结果所需的证据。

## 实体

实体是业务世界中可以被识别、引用和操作的对象。它可以是一个客户、一张订单、一项指标、一个语义模型、一张数据库表，也可以是知识图谱中的概念节点。

实体应具备：

- 稳定标识：例如外部键、内部实体 ID、ontology ID。
- 类型归属：例如 `semantic_indicator`、`database_table`。
- 可读名称：用于搜索、展示和解释。
- 属性集合：用于描述对象状态、字段、粒度、证据和运行上下文。

实体让系统能够定位具体资源中的具体对象，并携带其模型、字段、关系和查询契约等上下文。

## 关系与属性

关系表达实体之间的结构性联系，可以表示包含、引用、导航、依赖、派生或证据关联。例如，语义模型包含 Cube，数据库表包含列，SAP OData Entity Set 指向 Entity Type。

属性是实体和关系上的结构化描述，既可以承载业务信息，也可以承载运行信息：

- 资源状态、版本和更新时间。
- `analysis_contract`、`query_capabilities` 和 `key_schema` 等执行上下文。
- 别名、来源、置信度和引用样本等证据。
- 是否可写、是否支持 CSRF、是否截断同步等安全边界。

属性应尽量结构化，便于搜索、策略匹配和审计回放。

## 动作与策略

动作（affordance）描述对象可以如何被使用。例如，语义指标可以查询趋势，数据库表可以预览行，SAP Entity Set 可以读取集合或更新实体。策略则根据租户、组织、资源、目标和风险，决定动作是允许、拒绝还是需要审批。

本体中的动作必须带有明确的目标类型、输入 schema、风险等级、幂等要求和执行效果。这样，智能体可以发现可用能力，系统也能在执行前校验边界。

## 约束与校验

约束定义对象如何被合法使用：

- 类型约束：动作只能作用在指定实体类型上。
- 参数约束：动作输入必须满足 schema。
- 业务约束：写动作是否需要审批或幂等键。
- 运行约束：查询行数、同步对象数和源系统 metadata restriction。
- 权限约束：策略绑定决定 `allow`、`deny` 或 `require_approval`。

当系统无法确认目标对象、动作契约、参数合法性或策略结果时，应拒绝执行或转入审批，而不是让智能体自行猜测。这是本体系统的失败关闭原则。

## 从对象到执行

面向智能体的执行应沿着对象语义空间逐步推进：

```text
用户意图 → 对象定位 → 邻域上下文 → 动作发现 → 模拟校验 → 真实执行
```

- 对象定位确定用户指向的实体。
- 邻域上下文提供相关模型、字段、关系和约束。
- 动作发现说明对象当前可以执行的操作。
- 模拟校验检查参数、策略和运行条件。
- 真实执行调用适配器并记录结果。

上下文按任务阶段渐进披露：先提供资源和实体候选，再提供邻域、schema、动作契约、风险和审批信息，最后提供结果、审计证据和复盘信息。这样可以控制上下文成本，也能减少误用信息的风险。

## 语义与事实执行分离

本体层负责发现对象、关系、schema、约束和上下文；执行层负责调用外部资源、查询事实数据或触发写操作。例如，本体层可以说明指标属于哪个 Cube，但指标值仍由语义模型适配器回源查询；本体层可以描述 SAP Entity Set 的字段，真实读取仍由 SAP OData 适配器完成。

Ontology Snapshot、RDF 或本地投影保存可复用的语义事实，action manifest 和审计记录则分别保存执行契约与结果证据。由此，本体理论既保持语义一致，也尊重每个源系统的事实边界和权限边界。
