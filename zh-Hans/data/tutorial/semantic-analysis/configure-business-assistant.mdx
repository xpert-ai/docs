本教程以“采购查价助手 v1”为例，完成 **新建或编辑 → 基本信息 → 能力配置 → 资源与权限 → 检查并发布 → 实际查询验证**。

示例使用“采购”业务域、“采购用户组”和 `ProcurementPrices` 语义模型，请替换成自己的业务对象。操作在 Data Xpert 中完成，发布后可从相应助理入口使用。

## 1. 准备配置条件

- 当前账号可以维护目标工作空间中的业务助理。
- 所需运行服务、模型和插件可用；页面的组织准备状态没有阻断项。
- 目标语义模型已发布，并归属预期业务域。
- 已建立要使用助理的用户组，并加入实际使用者。
- 使用者拥有所需业务域、资源和查询权限。

需要先准备组织助理时，参见[初始化组织本体助理与建模助理](./initialize-organization-assistants)。已有可用语义模型时，不必为了创建业务助理再初始化一次组织助理。

| 配置项 | 决定什么 |
| --- | --- |
| 工作空间 | 助理配置保存在哪里，以及谁能进入维护 |
| 业务范围：个人或团队 | 助理显示在“我的助理”还是“团队助理” |
| 业务区域 | 助理的业务归属及相关访问范围 |
| 可访问用户组 | 哪些组的成员属于助理的使用人群 |
| 可访问资源 | 此助理可以调用哪些已授权资源 |
| 调用者自身权限 | 当前使用者实际能查询或操作哪些数据 |

选择“团队”不等于向全组织开放；选择业务域也不会自动绑定该域下的所有模型。使用助理和维护工作空间是不同权限，不必为了让普通成员聊天而开放整个工作空间的编辑权限。

## 2. 进入新建或编辑页面

打开 **AI 工作空间 → 目标工作空间 → 助理智能体**，进入“业务助理”列表。如果准备状态提示缺项，先点击 **查看详情**，按提示补齐对应运行条件。

### 新建业务助理

1. 点击右上角 **创建业务助理**。
2. 在“创建 Assistant”页面选择 **业务模板**。
3. 按下文填写基本信息、能力配置、资源与权限及发布检查。

页面可能同时提供“平台新建”和“绑定已有”入口。本教程使用“业务模板”；如果要接入已经发布的 Assistant，应走“绑定已有”，不要将其当作新模板助理重复创建。

### 编辑已有业务助理

在列表中找到目标助理，点击该行 **… → 编辑**。后续配置分区与新建流程一致。仅调整已有助理的用户组、资源或菜单设置时，使用编辑入口即可。

## 3. 填写基本信息

新建示例：

| 字段 | 示例或操作 |
| --- | --- |
| 名称 | 采购查价助手 v1 |
| 智能体编码 | `procurement_price_assistant_v1` |
| 业务范围 | 团队 |
| 业务区域 | 采购，与目标模型归属一致 |
| 菜单分类 | 可选，例如“价格查询” |
| 菜单排序 | 例如 `100`，按团队菜单约定设置 |
| 在菜单中显示 | 开启 |
| 描述 | 查询指定物料的采购价格、币种及适用条件 |

智能体编码同时用于业务助理和助理智能体的标识，应使用不重复的值，以字母或数字开头，仅包含字母、数字、下划线或连字符。已有“采购查价助手”时，新建 `v1` 是另一套配置；后续测试应打开这次发布的准确名称。

业务区域不是模型名称。先选择业务域，再到“资源与权限”中显式勾选要使用的模型。

## 4. 配置助理能力

进入 **能力配置**：

| 字段 | 配置方式 |
| --- | --- |
| 模板 | 选择插件提供的 `Business assistant with data-xpert tools` |
| 环境 | 选择当前工作空间中已准备好的、适用于该模板的环境 |
| MCP 实例 | 新建时可选择 **自动创建默认 MCP 工具集**；已有合适实例时按实际配置选择 |
| 渠道 | 按需配置；本教程不新增外部渠道 |

环境可能命名为 `Ontology Runtime` 或“语义模型 Workbench”。名称只是配置项的显示名称，应核对环境是否包含所需变量及运行配置，不要仅因名称与示例不同就新建或替换。默认 MCP 工具集由系统创建，无须在新建向导之外重复创建一份。

按业务需求维护助理指令。查价场景可使用以下约束：

```text
你是采购查价助手，仅使用本助理已授权且当前用户有权访问的资源。
按用户提供的物料号或图号查询采购价格，并说明币种、税口径和适用条件。
存在多条报价时先列出供应商、有效期等差异，请用户确认目标记录。
不要将多条单价直接相加；没有查询结果时明确说明，不编造价格。
```

指令用于约束业务回答，不能替代下一步的资源和用户授权。模板可能带有比查价更广的能力；助理自我介绍也不能证明某项操作已经获准或执行成功。

## 5. 配置使用人群和模型资源

进入 **资源与权限**，分别设置两部分。

### 5.1 选择可访问用户组

1. 在 **可访问用户组** 中选择“采购用户组”。
2. 确认目标组处于选中状态；当前主题下通常用填充背景突出选中项。
3. 如果同时看到 IT、法务和采购等候选组，仅被选中的组才进入本次组配置，看到候选名称不代表已经授权。
4. 核对实际使用者已加入所选用户组。多选组时，成员属于其中任意一个已选组即可满足组成员条件，其他访问条件仍要满足。

用户组是平台中的人员集合，可以对应部门，也可以跨部门。要开放给采购人员，应选采购用户组；若仅选 IT 组，采购人员不会因为“采购”字样出现在助手名称里而获得组授权。

<Note>
不要把“不选用户组”理解为“无人可用”。未指定组时仍需考虑现有业务域和分享规则。面向明确人群的助理应显式选组，并用普通成员验证菜单及直接链接访问。
</Note>

### 5.2 选择可访问资源

1. 在 **可访问资源** 中搜索目标模型，核对资源编码及模型标识。
2. 勾选 `ProcurementPrices` 对应的资源。
3. 切换 **已选** 查看结果，确认仅包含预期资源；本例应为 **已选 1**。

有些版本展示的是 `datax-semantic-model-<模型 ID>` 这样的资源编码，而不是业务模型名称；类型可能显示为 `business_ontology`。请用语义模型详情中的 ID 核对对应关系，不要凭列表位置、负责人名称或资源类型猜测。

**助理资源范围和用户自身权限同时生效。** 给助理勾选一个模型，不代表给所有助理使用者授予该模型权限；用户有权访问某个模型，也不代表该助理已经绑定了它。不要为了让助理可见而向普通使用者授予“业务区域管理”权限。

## 6. 保存并发布

1. 确认基本信息、能力配置、用户组和资源列表。
2. 点击 **保存草稿** 可先保留配置；仅保存草稿不会让修改向授权成员生效。
3. 准备生效时点击 **检查并发布**，进入 **发布检查**。
4. 检查全部结果。扩展能力应已注册、助理模板应可用并解析通过；存在其他失败项时先按提示处理，再 **重新检查**。
5. 核对摘要中的业务范围为“团队”、可访问资源为本例的“1 个资源”。填写发布说明，例如“仅向采购用户组开放采购价格模型”。
6. 等待保存完成且发布按钮可用，再点击发布；编辑已有助理时按钮为 **发布修改**。

出现 **有待发布修改** 表示草稿与已发布配置不同。发布成功后，应看到 **业务助理和助理智能体已创建并发布** 的成功提示，助理状态为 **已发布**；回到列表确认菜单状态为 **已启用**。

菜单启用只控制入口显示，不代替使用授权。关闭菜单也不能作为撤销直接链接访问权限的替代操作。

## 7. 打开助理并验收

由授权普通成员刷新助理列表，打开本次发布的“采购查价助手 v1”。菜单名称可能带有业务域前缀，请确认没有打开旧版同名助理。

先发送问候可检查聊天是否建立，再发送实际问题：

> 请查询物料 123456 的采购价格，并列出币种、是否含税、供应商和有效期。如果有多条记录，请先列出差异，不要合计单价。

用已知业务记录核对结果，并检查调用是否使用了预期语义模型。问候后返回能力清单，只证明当前会话能够响应，不能证明查价工具、模型绑定或数据权限已通过验证。

| 测试账号或场景 | 预期结果 |
| --- | --- |
| 所选组普通成员，具备目标资源及查询权限 | 能看到并打开助理，实际查询返回预期数据 |
| 不属于所选组、没有其他特殊授权的普通成员 | 不应看到该受限助理；持有直接链接也不能运行 |
| 所选组成员，但缺少目标数据权限 | 不应因拥有助理使用资格就取得该数据 |
| 助理未绑定的模型 | 不能通过此助理绕过资源范围访问 |
| 修改组或资源后 | 保存并重新发布，再验证新请求使用更新后的范围 |

权限验收使用普通成员账号。管理员可能具有额外管理或作者权限，不能用管理员的成功访问代替受限成员测试。

## 8. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 找不到业务模板 | 从准备状态详情检查插件注册、模板可用性和当前工作空间条件 |
| 用户组显示了却没有生效 | 确认真正选中、用户已入组，并已发布修改 |
| 保存后成员仍看到旧配置 | 检查是否只有草稿，完成发布后刷新并发起新请求 |
| 能看到助理但查不到模型 | 核对资源 ID、模型发布状态、业务域归属及调用者的数据和查询权限 |
| 新助理测试结果仍像旧助理 | 核对打开的名称、编码和实际发布对象 |
| 回复说能建模或执行动作 | 这只是回复内容，实际操作仍需工具、资源及动作权限；按业务需要收窄指令和配置 |

建模、授权及问数的完整流程见[从语义建模到业务助理问数](./modeling-to-business-assistant)。
