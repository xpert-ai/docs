语义模型把物理数据源转换为可查询、可管理的业务结构。当前系统有两条工作方式：

| 类型 | 数据来源 | 工作台重点 | 查询语言 |
| --- | --- | --- | --- |
| `SQL` | 关系型数据库或 SQL 连接服务 | 事实表、关系、维度、度量、计算成员 | SQL |
| `XMLA` | SAP BW、Analysis Services 等 XMLA 服务 | 远程数据立方体结构信息、系统名称、变量和度量绑定 | MDX |

## 模型的生命周期

- **草稿**：可编辑的草稿。工作台编辑会自动保存并递增草稿版本号。
- **已发布**：通过模型质量检查并发布后的版本。已发布版本号递增，下游查询和指标只使用已发布快照。
- **已归档**：不再作为当前资产使用的归档状态。

模型对象可以被分配到业务域。工作区成员从业务域继承访问权限，模型工作台的访问控制区域显示有效访问范围。

## 关系型模型对象

- **事实表**：数据立方体聚合的主表。
- **度量**：事实表中的可聚合数值列，例如订单金额；定义源列、数据类型、聚合器和格式。
- **维度**：用于切分事实的业务对象，例如客户、产品和时间。
- **层次结构**：维度中的导航路径。
- **层级**：层次结构的具体粒度，例如年、月、日。
- **计算成员**：在数据立方体中用表达式计算的字段。

## XMLA 模型对象

XMLA 模型不会把远程数据立方体投影为本地关系表，而是保存远程的数据立方体、维度、层次、层级、度量和 SAP 变量系统名称。刷新结构信息后，工作台用 `有效`/`缺失` 标记绑定是否仍然存在；缺失绑定必须修复后才能发布或执行指标。

## 查询与发布边界

查询工作台执行的是已选择模型的只读查询。SQL 模型不能用 MDX 运行，XMLA 模型不能用 SQL 运行。指标查询还要求指标和绑定模型均为 `已发布`；仅保存草稿不会改变线上结果。
