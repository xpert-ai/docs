本体工作室右上角的**助手**按钮负责打开或收起浮窗。要在浮窗中对话，管理员还需要初始化**当前组织本体助理**。这个组织级配置可以供多个本体复用，不需要为每个本体重复创建助手。

如果浮窗显示“尚未配置统一本体语义执行专家”，说明当前组织没有生效的本体助理绑定。此时的**打开探索助手**会切换工作室的探索入口，不会代替管理员完成初始化。

<Info>
**初始化角色：**`SUPER_ADMIN`。**使用角色：**有目标本体权限的组织成员。Studio 使用本体助理；**语义模型建模助理**用于语义模型工作台，不能替代这里的配置。
</Info>

## 1. 检查运行环境

先确认以下条件：

- Data Xpert 已连接真实的 Xpert API 和 OIDC 登录服务，用户能够正常登录。
- Xpert 与 Data Xpert 中选择的是同一组织。
- 当前组织有可用的协同模型，并已配置相应模型服务凭据。
- **系统管理 → 平台初始化 → 租户本体运行时**显示运行凭据及所需托管插件就绪。
- Xpert 能连接 Data Xpert 的 MCP 服务。

仅能打开 Studio、展示图谱或显示“已配置”状态，还不能证明模型推理和工具执行可用。

<Accordion title="本地部署的连接配置（运维人员）">
这些地址应指向同一套实际运行的服务。检查启动进程采用的配置，尤其注意命令行环境变量可能覆盖 `.env`。

| 配置 | 作用 |
| --- | --- |
| `XPERTAI_API_URL` | Data Xpert 后端使用的 Xpert API 地址，包含 `/api` |
| `OIDC_ISSUER`、`OIDC_CLIENT_ID`、`OIDC_AUDIENCE` | 后端校验真实登录令牌所需的发行方、客户端及受众 |
| `VITE_XPERTAI_API_URL`、`VITE_OIDC_ISSUER`、`VITE_OIDC_CLIENT_ID` | 前端对应的 Xpert API 与登录服务配置 |
| `VITE_API_BASE_URL` | 前端使用的 Data Xpert API 地址 |
| `DATA_XPERT_PUBLIC_MCP_URL` | Xpert 可访问的 MCP 地址，路径为 `/v1/mcp`，不是 `/api/v1/mcp` |
| `DATA_XPERT_API_BASE_URL` | 托管插件回调 Data Xpert 的服务根地址 |
| `DATA_XPERT_WEB_BASE_URL` | 插件打开 Data Xpert 页面时使用的 Web 地址 |

例如，Data Xpert API 监听本机 `5189` 时，MCP 地址可以是 `http://localhost:5189/v1/mcp`，插件 API 根地址可以是 `http://localhost:5189`。这些例子仅适用于 Xpert 也能通过相同的 `localhost` 访问该进程的情况；在容器或另一台机器中，应使用实际可达的服务地址。

确认 OIDC 客户端已登记 Data Xpert 的登录回调地址。修改连接配置后重启受影响服务，再通过正常登录流程进入系统。用于展示页面的临时身份服务不能替代真实的模型与助手运行时。
</Accordion>

## 2. 初始化组织本体助理

进入 **系统管理 → 平台初始化 → 当前组织本体助理**，依次完成：

1. **选择工作空间**：选择当前组织的共享工作空间。没有合适空间时，使用**初始化默认工作空间**。
2. **创建环境**：保留默认的 `oidc_token` 和 `business_assistant_id` 密钥变量，初始值留空，由运行时传递当前调用上下文。
3. **创建 MCP 工具集**：使用部署配置提供的地址和传输方式，保留默认请求头变量引用。
4. **导入 Xpert DSL**：选择当前的**本体助理**模板及可用的协同模型，开启**启用助理绑定**，然后点击**开始初始化**。

完整字段说明和请求头示例见[初始化组织本体助理与建模助理](../tutorial/semantic-analysis/initialize-organization-assistants)。已有可用的组织助理时，先检查当前绑定，无需另建同名助理。

完成后核对**已配置**状态、当前绑定、工作空间和最近初始化时间。模板显示名称可能是“统一本体语义执行专家”；判断绑定时应同时核对标识和组织。

<Note>
Studio 还会检查绑定是否具备本体草稿编写工具。旧版本助理即使能够查询已发布实体，也可能出现“需要升级”提示。此时通过初始化页使用当前本体助理模板重新完成初始化和发布，再返回 Studio。只更改显示名称或打开浮窗不会补齐工具。
</Note>

## 3. 在 Studio 中开启

1. 打开**数据与本体 → 本体工作室**，进入要测试的本体。
2. 等待当前草稿保存完成；有保存失败或并发冲突时先处理。
3. 点击右上角**助手**。配置生效后，浮窗应显示实际对话界面，而不是未配置提示。
4. 选中一个实体类型，再发出明确的读取请求。工作室会把本体定义、草稿修订、当前工作区和选择上下文传给助手。

管理员刚完成初始化时，可以刷新 Studio 重新获取组织绑定。浮窗的移动、收起和尺寸调整只影响布局。

## 4. 用制造案例验收

先进行只读检查，再在测试草稿中验证修改。以下提示词中的实体编码应以实际模型为准。

| 检查 | 可直接使用的提示词 | 通过条件 |
| --- | --- | --- |
| 读取当前草稿 | “请通过工具读取当前本体草稿，报告定义名称和草稿修订号，列出实体类型。先不要修改或发布。” | 工具执行成功，结果与当前 Studio 草稿一致 |
| 读取选中实体 | 选中“生产工单”后发送：“请读取当前选中实体的稳定编码、全部字段和关联关系，先不要修改。” | 返回实际字段及关系，且属于当前本体 |
| 校验 | “请校验当前本体草稿，解释错误和警告，不要自动修复。” | 有校验工具结果；发现业务校验错误也应如实展示 |
| 有界修改 | “仅将当前本体的描述改为‘汽车零部件制造验收草稿’，保留其他内容，不要发布。” | 修改工具成功，草稿修订号更新，界面同步显示；其他内容及已发布版本保持不变 |

最后一项应在测试本体中执行，或先记录原描述，测试后通过同一助手恢复原值。草稿修改与发布是两个步骤；需要发布时，另行在**版本**工作区校验并确认。

建议记录当前组织、本体名称、修改前后修订号、实际工具结果和截图。问候回复或文字上声称“已经修改”，不能替代工具成功与界面数据变化的证据。

组织复用助手不会授予额外本体权限。正式开放前，还应分别验证有权限成员可用、无权限成员仍无法读取或修改受限本体。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 仍显示“尚未配置” | 核对当前组织、启用绑定开关和初始化结果，刷新 Studio；“打开探索助手”不是初始化操作 |
| 显示需要升级本体助理 | 使用当前本体助理模板重新初始化并发布，确认草稿编写工具可用 |
| 初始化页没有可选模型 | 在当前组织配置模型服务及协同模型，确认当前账号可用 |
| MCP 地址不可达或没有发现工具 | 从 Xpert 所在环境检查 `/v1/mcp` 地址、传输方式和部署认证配置 |
| 会话创建失败或缺少 ChatKit client secret | 检查生效绑定、Xpert API 连接和会话请求错误；用户无需手工向浮窗填写密钥 |
| 能回复文字，不能读取草稿 | 检查实际工具调用、当前本体上下文、调用者权限和编写工具是否启用 |
| 助手修改后界面未更新 | 先检查工具是否成功；若存在本地未保存修改或修订冲突，按 Studio 提示处理，避免覆盖 |
| 只能查询已发布对象，结果与草稿不同 | 明确要求读取“当前 Studio 草稿”；本体空间的快照与 Studio 草稿可能处于不同版本 |
