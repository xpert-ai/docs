Open **Data Intelligence → Metric Management** and click **New** or an edit action. The current editor is a dialog; the old YAML bulk-registration flow is no longer supported.

## Basic fields

| Field | Description |
| --- | --- |
| Code | A stable code used to identify the metric in the workspace. Required. |
| Name | Display name. Required. |
| Type | Basic metric (BASIC) or derived metric (DERIVE). |
| Model | Semantic model used by the metric. A published model is recommended. |
| Description | Explanation of the metric definition. |
| Business definition | Definition written for business users. |
| Owner / validity | Optional owner and validity period. |

## Basic metrics (BASIC)

After you select an XMLA model, the editor loads available measures, levels, variables, and time grains from the cube. Select one measure, then add dimension bindings, filters, variables, or a time dimension as needed.

## Derived metrics (DERIVE)

A derived metric accepts a formula. For XMLA, use a restricted MDX value expression that references at least one existing measure; do not submit a complete SELECT statement, comments, or modification statements. Relational drafts still save formulas and filter definitions, subject to current validation support.

## Save, publish, and delete

Save updates only the draft. Return to the list to search by name, code, or description and filter by Draft, Published, or Archived. Publishing checks model bindings, measures, dimensions, and filters. Deletion requires confirmation and may be refused for a published metric or a metric referenced by another asset.

See [Basic and derived metrics](./derived-indicator) and [Metric dimensions and conditions](./qualification-condition).
