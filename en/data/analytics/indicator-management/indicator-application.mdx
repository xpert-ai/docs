Click **Query** in the metric list. The system reads the published metric and its semantic model, generates SQL or MDX, and returns a normalized result.

## Requirements

- The metric is **Published**.
- Its model is **Published** and contains the referenced cube and measure.
- XMLA variable, dimension, and filter bindings are valid.

## Result details

The result window shows the metric name, code, model version, cube, measure or expression, language, and table result. The generated SQL or MDX is included for review and troubleshooting. User variables, filters, and time grain appear in the execution context.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| The metric is still a draft | Return to the list, fix publishing errors, and click **Publish**. |
| The model version does not match | Publish the model again and confirm that the metric references an existing cube. |
| An XMLA measure or level is missing | Refresh the XMLA structure, repair the metric binding, and publish again. |
| A required variable is missing | Enter it when querying or set a default value in the model. |

Metric queries are read-only and follow the metric definition. For exploratory SQL or MDX, use the [Query workspace](../semantic-model/query-lab).
