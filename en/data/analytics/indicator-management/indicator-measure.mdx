A metric has a defined source and calculation meaning. When you create one, the system links it to a cube, measures, dimensions, and variables in a semantic model.

## Binding fields

- **Semantic model**: the model used by the metric.
- **Cube**: the target cube in an XMLA model.
- **Value source**: an existing measure or a restricted MDX expression.
- **Analysis dimensions**: levels users can use to view results.
- **Member filters**: members to include or exclude.
- **Variables**: values or ranges required by an SAP query.
- **Time settings**: default time dimension and grain.

The editor shows options available in the selected model. If no measures are available, refresh the remote structure in the XMLA workspace first.

## Publish and run

Save the binding, check certification and model version, then click **Publish**. Publishing confirms that the cube, measure, dimensions, levels, members, and variables still exist. When you click **Query**, the system generates SQL or MDX from these settings and shows the data in the result window.

## Invalid bindings

A remote cube change can mark an old binding as **Missing**. Refresh the preview in the model workspace, confirm the change, choose the binding again, and save. Do not try to repair it by changing only the display name. Certify again when required, then publish the metric.
