A metric definition has an analysis range and fixed conditions. Dimension bindings determine which fields can be grouped; filters and variables provide fixed or interactive conditions.

## Dimension bindings

In the XMLA metric editor, choose a dimension → hierarchy → level from the current cube. The selected level is stored in the binding and returned in query results. Do not type a display name in place of the unique name.

## Member filters

A filter contains a dimension binding, an Include or Exclude operator, and a member unique name. First find the member in **Members** in the workspace, then copy its exact unique name. Keep multiple filters clear and avoid contradictory Include and Exclude combinations.

## SAP variables and time

Required variables in an XMLA/SAP cube need a default value or a value supplied at query time. A metric can bind a time dimension and default grain such as year, quarter, month, week, or day. Query-time ranges and grains remain subject to model and metric checks.

## Publishing checks

The system checks that cubes, measures, levels, members, and variables still exist. If a structure refresh marks a binding as Missing, return to the XMLA workspace, click **Refresh preview**, fix the metric binding, and publish again.
