Open a model from the model list to enter its workspace. The top bar shows the model name, draft and publish status, auto-save status, and published version. The assistant is available on the right.

## Workspace navigation

### Data preparation

- **Data source browser**: refresh catalogs and structure, search tables, inspect columns, preview data, and view model definitions.

### Semantic design

- **Dimensions**: add and edit dimensions, hierarchies, levels, and member previews.
- **Cube**: choose a fact table, maintain fact-to-dimension relationships, and configure measures and the usage preview.
- **Calculations**: maintain calculated-member names, dimensions, and expressions.

### Validation and use

- **Query lab**: run SQL or MDX in the current model context.
- **Members**: find members by model, cube, dimension, hierarchy, and level.
- **Model quality**: view scores, errors, warnings, hints, and publishing requirements.

### Governance and operations

- **Access control**: view inherited business-domain access and certified metrics.
- **Run and cache**: refresh structure, run query probes, view run status, and review cache settings.
- **Model settings**: edit model settings and preferences.

## Drafts and auto-save

Relational model changes enter an auto-save queue. The top bar can show **Waiting to save**, **Saving**, **Synchronized**, **Conflict**, or **Error**. Wait for **Synchronized** before publishing, refreshing, or asking the assistant to modify the model. If a conflict appears, refresh the model and confirm the draft again. In an XMLA workspace, click **Save** for structure changes.

## Recommended order

1. Refresh the data source browser and confirm tables and columns.
2. Bind a fact table and measures to the cube.
3. Complete dimension keys, hierarchies, and levels.
4. Add calculated expressions when needed.
5. Validate in Model quality, then run a query probe in Run and cache.
6. Publish, then verify real results in the Query lab.
