Open **Data Intelligence → Semantic Models**. The list shows the models visible to your workspace, including their names, identifiers, data sources, types, catalogs, statuses, and published versions.

## Create a model

1. Click **Create**, then choose `SQL` (relational) or `XMLA` (remote multidimensional service).
2. Enter a name and data source. An identifier, description, catalog, and cube are optional, but the structure must be resolvable before publishing.
3. Catalog options are loaded from the data source. Do not put a SQL schema name in the XMLA cube field; they come from different structure information.
4. Save and click **Open workspace** on the model card.

For an XMLA source, you can also click **Import cube** on the data source card, run discovery, and choose a catalog and cube from the returned list.

## Search and edit

Search matches model name, identifier, description, catalog, and cube. **Edit** on a card changes basic information; edit structure in the workspace. Draft changes are saved automatically and remain visible after refreshing the list.

## Publish and versions

Before publishing, fix errors in **Model quality** and run a query probe in **Run and cache**. Click **Publish**, add release notes, and select a business domain when requested. After publishing:

- The status becomes **Published**.
- The published version increases from 0 or the previous version.
- Queries and metrics use this published version.
- Later edits create a new draft and require another publish.

## Delete and access

Deletion requires confirmation. The system may refuse to delete a published model or one still referenced by a metric; move downstream references first. **Access control** shows inherited business-domain members and certified metrics.
