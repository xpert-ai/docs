Dimensions let users slice facts by customer, product, organization, or time. The current editor is **Dimensions** in the model workspace.

## Relational model setup

1. Select the target cube in **Cube**, then open **Dimensions**.
2. Click **New dimension** and enter its name, display name, and description.
3. Add a hierarchy. Set its name, whether it includes an **All** member, and its dimension-table and key information.
4. Add one or more levels to the hierarchy. Enter each level name, display name, source column, and whether members are guaranteed to be unique.
5. Return to the cube relationship settings and fill in the fact-table foreign key and dimension primary key.
6. Confirm that values load in the member preview.

A time dimension commonly follows **year → quarter → month → day**. Keep the level order consistent with the way users drill into the data.

## XMLA model setup

XMLA dimensions come from the remote service. The workspace shows system names, display names, hierarchies, and levels. Do not use a display name as the association key; publishing and metric bindings use the remote system name. After a structure refresh, rebind or remove objects marked Missing.

## Quality requirements

Model quality checks that every dimension has a hierarchy, every hierarchy has levels with source columns, and every XMLA object still exists. After fixing an issue, wait for the draft to synchronize and click **Validate** again.
