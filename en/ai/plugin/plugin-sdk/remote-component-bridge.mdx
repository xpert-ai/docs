# Remote Component Host Bridge

The host bridge connects a Remote Component iframe, the Workbench host, and the plugin View Provider. It is not a generic RPC tunnel: business capabilities require their manifest declaration, a host handler and, where applicable, a server implementation. The common context lifecycle event is delivered without a subscription.

```text
Remote Component
  -> postMessage
  -> Workbench Host
  -> authenticated View Extension API
  -> IXpertViewExtensionProvider
```

The Remote Component sends business intent only. The host resolves the current user, host, tenant, and organization context and validates the view, feature, permissions, and capability declaration before calling the provider.

## Three contract layers

| Layer | Owner | Purpose |
| --- | --- | --- |
| Message protocol | Host and Remote Component | Defines iframe requests, responses, and lifecycle messages |
| View manifest | Plugin View Provider | Declares allowed data, actions, files, client commands, and events |
| Provider method | Plugin server | Runs a data query or business operation in a trusted server context |

The host must reject a capability when any layer is missing.

## Message envelope

All messages use a fixed channel and protocol version:

```ts
interface RemoteMessageEnvelope {
  channel: 'xpertai.remote_component'
  protocolVersion: 1
  instanceId?: string
  type: string
  requestId?: string
  scopeRevision?: number
}
```

- The iframe sends `ready` after loading.
- The host returns `init` with the `instanceId`, `runtimeScope`, `scopeRevision`, manifest, initial query, locale, theme and debug configuration.
- Later messages must carry the matching `instanceId`.
- Requests and responses share one `requestId`.
- The iframe accepts messages only from `window.parent`; the host accepts messages only from the current iframe `contentWindow`.

## Supported messages

Host to iframe:

| Message | Purpose |
| --- | --- |
| `init` | Initialize the manifest, query, locale, theme, and debug state |
| `hostEvent` | Forward subscribed business events or the common `view.context.changed` event |
| `data` | Response to `requestData` |
| `parameterOptions` | Parameter option response |
| `actionResult` | JSON action response |
| `fileActionResult` | File action response |
| `fileAccessResult` | File preview or download grant response |
| `clientCommandResult` | Client command response |
| `error` | Request-scoped error |

Iframe to host:

| Message | Purpose |
| --- | --- |
| `ready` | Request initialization |
| `resize` | Request iframe height in a non-fixed Workbench surface |
| `notify` | Request a host notification |
| `requestData` | Query view data |
| `requestParameterOptions` | Query dynamic parameter options |
| `executeAction` | Execute a JSON action |
| `executeFileAction` | Execute a file upload action |
| `requestFileAccess` | Request a file preview or download grant |
| `invokeClientCommand` | Request a host-local UI command |

## Capability mapping

| Capability | Manifest declaration | Iframe message | Server handling |
| --- | --- | --- | --- |
| Data query | `dataSource` | `requestData` | `getViewData` |
| Parameter options | `parameters[].optionSource` | `requestParameterOptions` | `getViewParameterOptions` |
| JSON action | `actions[].transport = 'json'` | `executeAction` | `executeViewAction` |
| File action | `actions[].transport = 'file'` | `executeFileAction` | `executeViewFileAction` |
| File access | `fileAccess.purposes` | `requestFileAccess` | `resolveViewFile` |
| Client command | `clientCommands[]` | `invokeClientCommand` | Host command registry |
| Host event | `hostEvents.subscriptions[]` | `hostEvent` | Host-managed |
| Remote entry | `view.type = 'remote_component'` | Host-managed | `getRemoteComponentEntry` |

## Context changes without remounting

For the same authenticated identity, organization and Assistant, changing Project or conversation preserves the iframe. The host reauthorizes the target View and entry, suspends operations while resolving it, then sends `view.context.changed` to every mounted View, including hidden tabs. No manifest subscription or acknowledgment is required.

`init.runtimeScope` and the event's `data.runtimeScope` are complete snapshots. Unbound fields are `null`; use the target snapshot rather than merging it with old IDs. The current Angular host supplies Project/conversation fields; hosts supporting group routing may also supply `groupId`.

```json
{
  "channel": "xpertai.remote_component",
  "protocolVersion": 1,
  "instanceId": "view-instance",
  "type": "hostEvent",
  "event": {
    "id": "context-change-2",
    "type": "view.context.changed",
    "source": "chatkit",
    "receivedAt": "2026-11-09T00:00:00.000Z",
    "data": {
      "revision": 2,
      "runtimeScope": { "projectId": null, "conversationId": "target-conversation" }
    }
  }
}
```

Revisions increase monotonically within one instance, not necessarily consecutively. Ignore stale revisions, reject pending work, clear selections and refresh or rebind against the new scope. Every subsequent request includes the latest `scopeRevision`. The host uses its own authorized context, never request-supplied scope, and rotates file sessions.

Changing identity, organization, Assistant or entry, explicitly reloading, or closing the View destroys the old instance. Denied entry access removes the previous document. Cancellation or a discarded response does not undo a server mutation already committed.

## TypeScript bridge client

Keep the bridge in `bridge.ts`; business components should not construct wire messages directly. This example targets hosts with context revisions and installs one bridge per iframe. Validate result payloads in typed business wrappers before using them.

```ts
const CHANNEL = 'xpertai.remote_component'
const VERSION = 1
const responses = {
  requestData: 'data',
  requestParameterOptions: 'parameterOptions',
  executeAction: 'actionResult',
  executeFileAction: 'fileActionResult',
  requestFileAccess: 'fileAccessResult',
  invokeClientCommand: 'clientCommandResult'
} as const

type RequestType = keyof typeof responses
type RuntimeScope = {
  groupId: string | null
  projectId: string | null
  conversationId: string | null
}
interface BridgeMessage {
  channel: typeof CHANNEL
  protocolVersion: typeof VERSION
  type: string
  instanceId?: unknown
  scopeRevision?: unknown
  runtimeScope?: unknown
  requestId?: unknown
  event?: unknown
  message?: unknown
  data?: unknown
  result?: unknown
}
interface PendingRequest {
  revision: number
  responseType: string
  resolve(value: unknown): void
  reject(error: Error): void
  timeout: number
}

let instanceId: string | null = null
let revision: number | null = null
let sequence = 0
const pending = new Map<string, PendingRequest>()
export const currentScopeRevision = () => revision

export function installBridge(handlers: {
  onInit(message: BridgeMessage): void
  onContextChange(scope: RuntimeScope, revision: number): void
  onHostEvent(event: unknown): void
}) {
  const listener = (event: MessageEvent<unknown>) => {
    if (event.source !== window.parent || !isBridgeMessage(event.data)) return
    const message = event.data
    if (message.type === 'init') {
      const scope = parseScope(message.runtimeScope)
      if (typeof message.instanceId !== 'string' || !scope ||
          !isRevision(message.scopeRevision)) return
      if (instanceId && message.instanceId !== instanceId) return
      if (revision !== null && message.scopeRevision < revision) return
      if (revision !== message.scopeRevision) rejectPending('view_context_changed')
      instanceId = message.instanceId
      revision = message.scopeRevision
      handlers.onInit(message)
      return
    }
    if (!instanceId || message.instanceId !== instanceId) return
    if (message.type === 'hostEvent') {
      const change = parseContextChange(message.event)
      if (change) {
        if (revision !== null && change.revision <= revision) return
        rejectPending('view_context_changed')
        revision = change.revision
        handlers.onContextChange(change.scope, revision)
        return
      }
      handlers.onHostEvent(message.event)
      return
    }
    if (typeof message.requestId !== 'string') return
    const request = pending.get(message.requestId)
    if (!request || request.revision !== revision) return
    if (message.scopeRevision !== undefined && message.scopeRevision !== revision) return
    if (message.type !== 'error' && message.type !== request.responseType) return
    pending.delete(message.requestId)
    window.clearTimeout(request.timeout)
    if (message.type === 'error') {
      request.reject(new Error(typeof message.message === 'string'
        ? message.message : 'remote_request_failed'))
    } else {
      request.resolve(message.data ?? message.result)
    }
  }
  window.addEventListener('message', listener)
  window.parent.postMessage({ channel: CHANNEL, protocolVersion: VERSION, type: 'ready' }, '*')
  return () => {
    window.removeEventListener('message', listener)
    rejectPending('remote_bridge_disposed')
    instanceId = null
    revision = null
  }
}

export function requestHost(type: RequestType, body: object) {
  const requestRevision = revision
  if (!instanceId || requestRevision === null) {
    return Promise.reject(new Error('remote_bridge_not_initialized'))
  }
  const requestId = `${Date.now()}-${++sequence}`
  return new Promise<unknown>((resolve, reject) => {
    const timeout = window.setTimeout(() => {
      pending.delete(requestId)
      reject(new Error('remote_request_timeout'))
    }, 30_000)
    pending.set(requestId, {
      revision: requestRevision, responseType: responses[type], resolve, reject, timeout
    })
    try {
      window.parent.postMessage({
        ...body, channel: CHANNEL, protocolVersion: VERSION,
        instanceId, scopeRevision: requestRevision, type, requestId
      }, '*')
    } catch {
      pending.delete(requestId)
      window.clearTimeout(timeout)
      reject(new Error('remote_request_not_cloneable'))
    }
  })
}

function rejectPending(code: string) {
  for (const request of pending.values()) {
    window.clearTimeout(request.timeout)
    request.reject(new Error(code))
  }
  pending.clear()
}
function isRevision(value: unknown): value is number {
  return typeof value === 'number' && Number.isSafeInteger(value) && value >= 0
}
function isId(value: unknown): value is string | null {
  return value === null || typeof value === 'string'
}
function parseScope(value: unknown): RuntimeScope | null {
  if (!value || typeof value !== 'object' ||
      !('projectId' in value) || !isId(value.projectId) ||
      !('conversationId' in value) || !isId(value.conversationId)) return null
  const groupId = 'groupId' in value ? value.groupId : null
  if (!isId(groupId)) return null
  return { groupId, projectId: value.projectId, conversationId: value.conversationId }
}
function parseContextChange(value: unknown) {
  if (!value || typeof value !== 'object' || !('type' in value) ||
      value.type !== 'view.context.changed' || !('data' in value)) return null
  const data = value.data
  if (!data || typeof data !== 'object' || !('revision' in data) ||
      !isRevision(data.revision) || !('runtimeScope' in data)) return null
  const scope = parseScope(data.runtimeScope)
  return scope ? { revision: data.revision, scope } : null
}
function isBridgeMessage(value: unknown): value is BridgeMessage {
  return !!value && typeof value === 'object' && !Array.isArray(value) &&
    'channel' in value && value.channel === CHANNEL &&
    'protocolVersion' in value && value.protocolVersion === VERSION &&
    'type' in value && typeof value.type === 'string'
}
```

In `onContextChange`, clear scope-dependent state before reloading or rebinding. If a wrapper does asynchronous processing after a response, capture `currentScopeRevision()` and compare it again before applying the processed result. Repeated `init` for the same revision may update theme/locale without resetting the selected resource.

Build named wrappers such as `requestData()`, `executeAction()`, and `invokeClientCommand()` on top of this boundary. Return stable error codes from the bridge and translate them at the UI boundary.

## Query data

```ts
const result = await requestHost('requestData', {
  query: {
    page: 1,
    pageSize: 20,
    search,
    parameters: {
      table: 'contracts',
      status
    }
  }
})
```

`XpertViewQuery.parameters` accepts only scalar values or scalar arrays. Serialize a complex filter into one explicit JSON string parameter and parse it safely in the provider.

Use server-side pagination for large tables. Do not load every record into the iframe.

## Execute actions

Use JSON actions for normal business mutations:

```ts
await requestHost('executeAction', {
  actionKey: 'approve_contract',
  targetId: contractId,
  input: { comment },
  parameters: { projectId }
})
```

The `actionKey` must exist in `manifest.actions`, and its transport must match. The provider still validates the target, current user, and tenant/organization scope.

Use `executeFileAction` for uploads; do not put binary or Base64 content in JSON actions. Use `requestFileAccess` for previews and downloads so the host can issue a time-bounded grant.

## Client commands

Client commands perform host-local UI behavior without calling the plugin provider. Examples include sending an Assistant message, setting Assistant context, opening a file, or navigating to another Workbench view.

They form a closed three-party contract:

1. The source manifest allowlists the command key in `clientCommands`.
2. The current host registers a handler for the same key.
3. The Remote Component invokes it through `invokeClientCommand` and handles a structured failure result.

```ts
import {
  WORKBENCH_NAVIGATION_OPEN_COMMAND,
  WORKBENCH_EXTENSION_VIEW_TARGET
} from '@xpert-ai/contracts'

await requestHost('invokeClientCommand', {
  commandKey: WORKBENCH_NAVIGATION_OPEN_COMMAND,
  payload: {
    target: WORKBENCH_EXTENSION_VIEW_TARGET,
    viewKey: 'contract_review__history',
    selectionId: contractId
  }
})
```

Do not navigate the top window directly from the iframe.

### Current host commands

| Command | Input and behavior |
| --- | --- |
| `workspace.connector.connect` | `{ provider, authMethodId?, integrationId? }`; opens authorized connector setup. Selecting an integration also requires its auth method. Success data reports `connected` or `cancelled`, without credentials. |
| `workbench.content.resolve` | `{ resourceId, providerKey }`; resolves an authorized content editor. Forward returned `navigation` unchanged to `workbench.navigation.open`. |
| `artifact.presentation.open` | `{ url: presentationUrl }`; opens the platform's authenticated Artifact viewer. Only platform `/artifacts/view/:slug` URLs are accepted. |

Declare each command you use, check structured results and surface unavailable handlers or blocked popups. A manifest does not guarantee that every host implements a command. Never add tenant/workspace identity or credentials to these payloads.

## Host events

A Remote Component can subscribe to normalized host events, such as a completed Agent middleware tool:

```ts
hostEvents: {
  subscriptions: [
    {
      key: 'contract-mutated',
      event: 'assistant.tool.completed',
      filter: {
        sources: ['chatkit'],
        toolNames: ['contract_update', 'contract_approve']
      },
      action: { type: 'forward', debounceMs: 800 }
    }
  ]
}
```

Declarative views normally use `refresh`. Prefer `forward` for Remote Components so they can refresh only the affected data. If local edits are dirty, do not silently replace them with remote state.

## Initialization, theme, and locale

Treat `init.locale` as authoritative and normalize it once to a BCP 47 tag such as `en-US`, `zh-Hans`, or `zh-Hant`. Do not select copy with locale branches inside business components.

After applying `init.theme.tokens`, call `installShadcnThemeVars()` to install semantic theme variables. Gate debug logging with `init.debug.enabled`; do not infer development mode from URLs, hostnames, or platform identity.

Do not rely on `localStorage` or `sessionStorage`. Keep ephemeral state in React and persist durable state through the host bridge.

## Security checklist

- Do not pass access tokens, API URLs, Assistant IDs, tenant IDs, or organization IDs into the iframe.
- Do not let the iframe select `hostType` or `hostId`.
- Reject actions, file capabilities, and client commands that are absent from the manifest.
- Do not log tokens, file contents, complete business snapshots, or personally sensitive data.
- Re-run authorization and tenant/organization isolation for every provider read and mutation.
- Test message source, protocol version, instance ID, request ID and revision boundaries, including a slow response after a context switch.
