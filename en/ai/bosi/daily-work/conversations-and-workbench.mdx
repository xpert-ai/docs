ChatKit provides Bosi's conversation area. Explain a goal, attach materials, select capabilities and inspect tool activity, then check results in the adjacent Workbench.

## Explain the requirements

A useful request identifies the subject, scope, expected output and actions needing confirmation. For example:

> Use this project's requirements to compare three approaches and list unresolved questions. Show a draft with sources first, and do not send it to the customer.

Use projects for ongoing collaboration. An Assistant that permits non-project conversations can handle temporary questions. Attachments, skills, plugins and connectors use the current conversation context; recheck selections after switching projects.

Tool activity helps establish what the Assistant actually did. Respond to approvals or requests for information in their own entries, and compare a “done” reply with real files, business records or acceptance results.

## Workbench beside the conversation

| View | What to inspect |
| --- | --- |
| Application business view | Forms, outlines, materials, business state and app-specific actions |
| Project tasks | Assignments, dependencies, planned dates, attempts and acceptance records |
| Files and results | Saved content, previews, versions and downloads |
| Live dashboard | Charts, filters, data refresh, draft and publication state |
| Cloud computer | The remote desktop process, with authorized takeover when needed |

Available views depend on the Assistant, project and app capabilities. Some open on demand through the add-view menu or an application entry. Opening a view does not itself start business work.

Resource cards open their associated project, business object or execution. Switching conversations reloads views in the new context. A retained historical card does not establish current access.

## Collaborate through realtime voice

When the published Assistant has realtime voice configured and the service supports it, choose **Call** in the conversation's Assistant panel and allow microphone access. The interface provides connection state, captions, task progress, mute and hangup controls.

Voice supports discussion, clarification and delegation. The Assistant still performs tools and longer tasks under its existing permissions. Voice and reasoning models are configured separately; enabling voice does not grant additional tool rights.

Muting or hanging up does not cancel accepted background tasks. Request cancellation of a specific task and inspect its actual state. Navigating to another chat does not transfer an active call: it remains bound to its original Assistant and conversation. The current desktop voice entry is for Assistant conversations, not a promise of group voice meetings.

## Inspect formal delivery

| What you see | What it establishes |
| --- | --- |
| Reply or output summary | An explanation to check against actual evidence |
| A working-directory path | A file's working location, not automatically a downloadable delivery |
| Formal file delivery card | A reference to the version saved at delivery, available for authorized preview and download |
| Application result entry | Business content and versions maintained by the app, confirmed through its workflow |

Open the delivery card and check its filename and contents. Supported formats can be previewed; others remain downloadable. The preview is tied to the delivered version, so a later modified file should not be substituted for the original result.

Reports, documents and dashboards may have drafts and formal versions. Before sharing or submitting, confirm the version and audience.
