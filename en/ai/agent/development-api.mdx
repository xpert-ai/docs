Use the official [XpertAI TypeScript SDK](https://github.com/xpert-ai/xpert-sdk-js), published as `@xpert-ai/xpert-sdk`, for new integrations in TypeScript or JavaScript projects. The SDK supports servers, scripts and backend workflows independently of ChatKit.

If your development environment uses Python, Java, Go or another language, use the TypeScript SDK implementation and the HTTP API reference below to build a client or SDK in that language. Preserve the authentication, request and response structures, SSE event handling and reconnection behavior. Follow the latest official documentation and TypeScript SDK source for current usage.

<Warning>
Legacy AI/v1 OpenAPI integration, such as `POST /api/ai/v1/chat`, is deprecated and no longer maintained; availability is not guaranteed. This notice applies to old endpoints. The SDK use cases below remain available and have been updated to use the official SDK.
</Warning>

## Before you start

1. Publish the agent and obtain its ID (`xpertId`).
2. Create an API Key with access to that agent and store it in a server environment variable.
3. Set `XPERTAI_API_URL`, for example `https://api.xpertai.cn/api/ai`. Use your own address for private deployments; do not append `/v1`.
4. Use Node.js 18 or later and install the SDK:

```bash
npm install @xpert-ai/xpert-sdk
```

## Start a conversation with the SDK

This example creates a thread and starts a run, then waits for its result. Set `XPERTAI_API_KEY` and `XPERTAI_XPERT_ID` before running it.

```ts
import { Client, type ChatSendRequest } from "@xpert-ai/xpert-sdk";

async function main() {
  const apiKey = process.env.XPERTAI_API_KEY;
  const xpertId = process.env.XPERTAI_XPERT_ID;
  if (!apiKey || !xpertId) {
    throw new Error("Set XPERTAI_API_KEY and XPERTAI_XPERT_ID");
  }

  const client = new Client({
    apiUrl: process.env.XPERTAI_API_URL ?? "https://api.xpertai.cn/api/ai",
    apiKey,
  });
  const thread = await client.threads.create({ assistantId: xpertId });
  const input: ChatSendRequest = {
    action: "send",
    message: { input: { input: "Hello, what can you help me with?" } },
  };
  const result = await client.runs.wait(thread.thread_id, xpertId, { input });

  console.log("thread_id:", thread.thread_id);
  console.log(result);
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

Save `thread.thread_id` and reuse the thread for subsequent messages with `client.runs.wait()` or `client.runs.stream()`.

For an agent conversation, pass `assistantId` when creating the thread and use the same agent ID for subsequent runs. The SDK serializes `assistantId` as the HTTP field `assistant_id`. The protocol allows omission to create an unbound thread under the current request identity. If a later run uses a different execution identity, conversation access checks can return 403. Binding the agent at creation establishes its scope early; it does not grant additional access.

### Thread creation succeeds, but the run returns 403

`201 Created` confirms thread creation, not permission to run the agent. If a run returns `You do not have access to this conversation`:

1. Confirm that the API Key can access the published agent. Create a new thread with `client.threads.create({ assistantId: xpertId })`, then pass the same `xpertId` to the run. Changing the example does not repair a previously created thread.
2. Use the same credentials and caller identity when creating and running the thread. Do not reuse a thread belonging to another user or an unrelated agent.
3. If a new, bound thread still returns 403, have the administrator check the API Key's effective caller, the conversation's owner (`createdById`) and agent binding (`xpertId`), and the deployed server version. Supplying `assistantId` does not bypass ownership or scope checks and cannot resolve every 403.

## Receive streaming output

For real-time progress, replace the `runs.wait()` call in the same `main()` function with:

```ts
for await (const chunk of client.runs.stream(thread.thread_id, xpertId, { input })) {
  console.log(chunk.event, chunk.data);
}
```

For streaming calls, check run completion, error and interrupt events. HTTP success or a closed connection alone does not prove the task succeeded. Reconnect to an existing run with `client.runs.joinStream(threadId, runId)`; it subscribes to an existing run and does not start a new one.

To print only answer text as it arrives, replace the loop above with the following. Handle other events in your application's lifecycle logic; filtering text alone does not establish whether the run succeeded.

```ts
for await (const chunk of client.runs.stream(thread.thread_id, xpertId, { input })) {
  const event = chunk.data;
  if (!event || typeof event !== "object" ||
      !("type" in event) || event.type !== "message" || !("data" in event)) continue;

  const data = event.data;
  if (typeof data === "string") {
    process.stdout.write(data);
  } else if (data && typeof data === "object" &&
             "type" in data && data.type === "text" &&
             "text" in data && typeof data.text === "string") {
    process.stdout.write(data.text);
  }
}
```

## Query agents

The snippets below reuse `client`, `xpertId`, `thread` and `input` from the first example. Use them as needed in the same `main()`. They retain the original agent, thread, run and storage use cases.

### Search and retrieve an agent

```ts
const xperts = await client.assistants.search({ limit: 10, offset: 0 });
const xpert = await client.assistants.get(xpertId);
console.log(xperts, xpert);
```

## Create and manage threads

### Specify a thread ID

```ts
const { randomUUID } = await import("node:crypto");
const customThread = await client.threads.create({
  assistantId: xpertId,
  threadId: randomUUID(),
  ifExists: "raise",
});
console.log(customThread.thread_id);
```

This specifies the creation ID; it does not pre-fill agent state.

### Read thread lists, details and current state

```ts
const threads = await client.threads.search({ limit: 10, offset: 0 });
const currentThread = await client.threads.get(thread.thread_id);
const state = await client.threads.getState(thread.thread_id);
console.log(threads, currentThread, state);
```

Current state comes from the thread checkpoint and can be read after the first run. See the compatibility section for `getHistory()` support.

### Continue a conversation in the same thread

```ts
const followUp: ChatSendRequest = {
  action: "send",
  message: { input: { input: "Please continue the previous topic." } },
};
const nextResult = await client.runs.wait(thread.thread_id, xpertId, {
  input: followUp,
});
console.log(nextResult);
```

Reuse the existing thread ID instead of creating a thread for every message.

## Background runs and run management

### Create a background run

```ts
const run = await client.runs.create(thread.thread_id, xpertId, { input });
console.log(run.run_id);
```

`create()` returns a run record while execution continues in the background. `wait()` starts a new run and waits for its result. These are alternative invocation styles; do not call both for the same message.

### Read status and list runs

Reuse `run.run_id` returned by background creation:

```ts
const currentRun = await client.runs.get(thread.thread_id, run.run_id);
const runs = await client.runs.list(thread.thread_id, { limit: 10, offset: 0 });
console.log(currentRun.status, runs);
```

### Cancel an active run

Execute this when cancellation of that run is intended:

```ts
await client.runs.cancel(thread.thread_id, run.run_id);
```

## Reconnect to an existing run

Save `thread_id` and `run_id` from creation. Streaming creation also exposes the run ID through the `onRunCreated` callback of `runs.stream()`. After a disconnection, use `joinStream()` to subscribe to that existing run:

```ts
for await (const chunk of client.runs.joinStream(thread.thread_id, run.run_id)) {
  console.log(chunk.event, chunk.data);
}
```

This subscribes to an existing run instead of starting another task. A new `runs.create()` or `runs.wait()` call is not a reconnection and can repeat execution.

## Upload an attachment before a conversation

Upload through the current SDK's `contexts` client, then pass the returned file handle to the agent:

```ts
const { readFile } = await import("node:fs/promises");
const buffer = await readFile("./manual.pdf");
const file = await client.contexts.uploadFile<{ id: string; url?: string }>(
  new Blob([new Uint8Array(buffer)]),
  { filename: "manual.pdf" },
);
const attachmentInput: ChatSendRequest = {
  action: "send",
  message: {
    input: { input: "Summarize the attachment.", files: [file] },
  },
};
const attachmentResult = await client.runs.wait(thread.thread_id, xpertId, {
  input: attachmentInput,
});
console.log(attachmentResult);
```

## Persistent Store

Store examples remain available for saving and reading data across runs. Use the agent ID as the first namespace segment; this example adds a child namespace.

### Write and read

```ts
const namespace = [xpertId, "sdk-example"];
await client.store.putItem(namespace, "key1", { value: 42 });
const item = await client.store.getItem(namespace, "key1");
console.log(item);
```

### List namespaces and search data

```ts
const namespace = [xpertId, "sdk-example"];
const namespaces = await client.store.listNamespaces({
  prefix: [xpertId],
  maxDepth: 2,
  limit: 10,
});
const found = await client.store.searchItems(namespace, { limit: 10 });
console.log(namespaces, found.items);
```

`searchItems()` accepts the namespace array as its first argument and query options as its second. Semantic `query` search requires the appropriate memory model configuration; the example only lists data in the namespace.

## Compatibility and unsupported calls

A method exposed by the SDK is not proof that the target deployment implements its server capability. In the current platform source, the following calls from the old examples cannot be presented as runnable cases:

| Call | Current platform status | Integration guidance |
| --- | --- | --- |
| `threads.getHistory()` | Server-side history query is not implemented | Read the current thread and `getState()`; neither is a complete history |
| `threads.updateState()`, `threads.update()` | Server-side state updates and thread PATCH are not implemented | Use supported run inputs and conversation operations |
| `runs.join()` | No corresponding server-side join route | Use `wait()` for a new run, or `get()` / `joinStream()` for an existing run |

These are specific support limits, not deprecation of agent queries, thread management, runs or Store examples. Verify SDK and server versions for private deployments.

## HTTP API reference

For direct HTTP integration, the **HTTP API Reference** sidebar group provides method badges, request fields, responses, cURL examples and a playground for the endpoints used above. These are the current SDK endpoints, independent of ChatKit. Authenticate with your server-side API Key using `Authorization: Bearer <API_KEY>` or `x-api-key`.

Start by [creating a thread](/en/sdk-api/threads/create-thread), then [start a streaming run](/en/sdk-api/runs/stream-run), or [create a background run](/en/sdk-api/runs/create-run). To recover an interrupted connection, [subscribe to the existing run](/en/sdk-api/runs/join-run-stream); do not start the same task again.

| SDK capability | HTTP reference |
| --- | --- |
| `client.assistants.search()` / `get()` | [Query agents](/en/sdk-api/assistants/search-assistants) |
| `client.threads.create()` / `search()` / `get()` / `getState()` | [Create and manage threads](/en/sdk-api/threads/create-thread) |
| `client.runs.stream()` / `create()` / `wait()` / `get()` / `list()` / `cancel()` / `joinStream()` | [Start and manage runs](/en/sdk-api/runs/stream-run) |
| `client.contexts.uploadFile()` | [Upload an attachment](/en/sdk-api/contexts/upload-file) |
| `client.store.putItem()` / `getItem()` / `listNamespaces()` / `searchItems()` | [Store data](/en/sdk-api/store/put-store-item) |

HTTP wire fields can differ from SDK option names: for example, `assistant_id`, `thread_id` and `max_depth`. Use the request schema on the specific endpoint page. This reference covers the guide's examples; methods listed above as unsupported are not presented as available endpoints.
